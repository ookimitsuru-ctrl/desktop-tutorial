# ROLLERDASH ARENA

[![Android](https://github.com/ookimitsuru-ctrl/desktop-tutorial/actions/workflows/android.yml/badge.svg)](https://github.com/ookimitsuru-ctrl/desktop-tutorial/actions/workflows/android.yml)

Android 向けの 3D ロボット対戦ゲーム。
機体デザインは『装甲騎兵ボトムズ』の AT（アーマードトルーパー）——ずんぐりした円筒胴、
スライドする単眼のターレットレンズ、脚部ローラーによるローラーダッシュ——をモチーフに、
ゲームシステムはセガ『電脳戦機バーチャロン』の 1 対 1 立体戦闘（ロックオン、ダッシュ、
ジャンプ、ダッシュ攻撃、しゃがみリロード、3 ラウンド制）を土台にしています。

エンジンは使っていません。Kotlin + OpenGL ES 3.0 のフルスクラッチで、
**モデル・テクスチャ・効果音のアセットファイルはゼロ**です。機体もフォントも爆炎も、
すべて実行時に手続き的に生成しています（音は AudioTrack 上の自前ミキサで合成）。

---

## ビルド済み APK を入れる（ローカル環境が不要な方法）

GitHub Actions が push のたびに debug APK をビルドして成果物に添付します。
Actions のページから `rollerdash-arena-debug-apk` をダウンロードし、
zip を展開して `app-debug.apk` を端末にインストールしてください
（提供元不明のアプリの許可が必要です）。PC 経由なら `adb install -r app-debug.apk`。

## ソースからビルドする

Android Studio（Ladybug 以降）でこのディレクトリを開くか、コマンドラインから:

```bash
./gradlew :app:assembleDebug          # APK を作る
./gradlew installDebug                # 接続中の実機に入れる
./gradlew :core:test                  # 戦闘シミュレーションのユニットテスト

tools/run_on_device.sh                # ビルド→インストール→起動→ログとフレーム統計を収集
```

`tools/run_on_device.sh` は実機を繋いだ状態で 1 回叩けば、クラッシュ・GL エラー・
実測フレームタイム（`dumpsys gfxinfo`）を `device-report.txt` にまとめます。
不具合報告はこのファイルを渡すのが一番早いです。

* 必要環境: Android SDK（compileSdk 35）、JDK 17 以上、minSdk 26、OpenGL ES 3.0 対応端末
* 依存ライブラリは **なし**（`:app` は `:core` にのみ依存）
* 画面は横向き固定・全画面

## 操作

### MODERN（初期設定・スマホ向け）

| 操作 | 割り当て |
| --- | --- |
| 移動 | 左スティック（前後左右。ロックオン中は自動で敵を向く） |
| 旋回 | 画面右側を左右にドラッグ |
| 左右反転 | タイトルの `LAYOUT` で左利き配置に切り替え |
| RW（右武器） | `RW` ボタン |
| LW（左武器） | `LW` ボタン |
| CW（中央武器） | `CW` ボタン（= RW + LW 同時押し） |
| ローラーダッシュ | `DASH`（移動入力の方向へ。空中で押せば空中ダッシュ） |
| ジャンプ／ホバー | `JUMP`（押しっぱなしでブースト上昇） |
| しゃがみ（ガード＋高速リロード） | `GUARD` |
| ポーズ | 右上の `MENU`、または戻るキー |

### TWIN STICK（アーケード筐体準拠）

タイトル画面の `CONTROL` で切り替え。左右 2 本のレバー + トリガ + ターボの配置です。

| 入力 | 動作 |
| --- | --- |
| 両レバー前／後 | 前進／後退 |
| 両レバー左／右 | 横移動（サイドステップ） |
| 左右レバーを逆方向 | その場旋回 |
| ターボ + レバー | ローラーダッシュ |
| ターボ同時押し | ジャンプ |
| 右トリガ／左トリガ | RW／LW |
| トリガ同時押し | CW |
| `GUARD` | しゃがみ（タッチ操作用に独立ボタン化） |

### ゲームパッド

物理コントローラを接続すると自動で認識します。左スティック=移動、右スティック=旋回、
L1/R1 と L2/R2=LW/RW、Y=CW、A=ジャンプ、B=ダッシュ、X=ガード、START=ポーズ。
メニューは十字キー + A で操作できます。

## 見た目（描画パイプライン）

エンジンなし・テクスチャファイルなしのまま、1 フレームは以下の順で作られます。

1. **シャドウマップ** — 太陽から 2048x2048 の深度を描き、4 タップ PCF で受け取る
2. **シーン描画** — リニア空間の浮動小数点バッファへ。太陽 + 半球アンビエント +
   **動的ポイントライト 4 灯**（発砲炎・爆発・格闘の火花が機体と地面を実際に照らす）
3. **ブルーム** — 輝度抽出 → 分離ガウシアン（半解像度）
4. **合成** — ACES トーンマップ、ブルーム合成、周辺減光、粒子、色収差、
   スプリットトーン（影を寒色・ハイライトを暖色）、ダッシュ中の放射ブラー
5. **FXAA** → HUD（最後に描くので文字は常にくっきり）

表面のディテールはすべて手続き生成です。装甲にはパネルライン・角の塗装剥げ・
スミ入れ、コンクリートには骨材の斑・ひび、床にはスラブ目地・区画ペイントの掠れ・
ダッシュの軌跡・こぼれた燃料（そこだけ光る）が乗ります。

アリーナの外周には廃墟のスカイライン、内側には瓦礫・ドラム缶・投光器・
先のラウンドで大破した AT が置かれています。撃破時は**スローモーションに落ちて
カメラが残骸に寄ります**。

タイトルの `GRAPHICS` で HIGH / BALANCED / PERFORMANCE を切り替えられます
（PERFORMANCE は影とブルームを落とします）。フレームレートが落ちる端末ではここを下げてください。

## ゲームシステム

* **ロックオン** — 常時、敵の方向へ機体が自動で向きます。射線が遮蔽物で切れるとレティクルが開き、
  通れば閉じて `LOCK` 表示。さらに射撃時は照準計算が入り、**移動先を偏差射撃**し、
  跳んだ敵には仰角を、迫撃系には放物線の射角を自動で付けます（機首から最大 23 度まで）。
  当たり判定にも 0.9 m の余裕があるので、掠める弾はヒット扱いです。
  タイトルの `LOCK-ON` を `MANUAL` にすると補正が切れ、機体正面へまっすぐ飛びます
  （敵 AI は常に MANUAL 側で、偏差は自分の旋回だけで取っています）。
* **ローラーダッシュ** — 脚部ローラーによる高速滑走。ブーストゲージを初動＋持続で消費し、
  終わり際に硬直が残ります。壁に当たるとキャンセル。
* **スタンス別の攻撃** — 同じボタンでも **地上／ダッシュ中／空中** で別の攻撃が出ます
  （例: SCOPE HOUND の RW は 地上=4 点バースト、ダッシュ=7 点掃射、空中=ストラーフ射撃）。
  ダッシュ攻撃はダッシュ自体をキャンセルしつつ慣性だけ残るので、そこが立ち回りの肝です。
* **CW（中央武器）** — 弾数 1、リロードが最も遅い切り札。近接系の機体はここが格闘になります。
* **しゃがみ** — 移動できない代わりに、弾倉とブーストが一気に回復し、被ダメージが 45% 減。
  引き撃ちの合間にどこで屈むかがリソース管理です。
* **よろけとダウン** — 攻撃には威力とは別に「衝撃値」があり、累積するとダウン。
  起き上がりには短い無敵があります。機体重量が重いほど耐えます。
* **ラウンド制** — 90 秒 3 ラウンド、先取 2 本。時間切れは残装甲の多い方が勝ち。

## 機体（4 種）

| 機体 | 特徴 | 装甲 | 主武装 |
| --- | --- | --- | --- |
| **SCOPE HOUND** (ATM-09-ST) | 標準量産機。癖がなく最初の 1 機に | 1000 | ヘビィマシンガン／ミサイルポッド／ソリッドシューター・アームパンチ |
| **FANG HOUND** (ATH-14-WP) | 赤い強襲型。重装甲・近距離火力 | 1220 | ショットカノン／火炎放射／ショルダーラム |
| **STANDING TORTOISE** (ATM-03-ST) | 砲戦型。鈍重だが遠距離から試合を終わらせる | 1450 | ロングカノン／臼砲斉射／シージランス |
| **BERSERK HOUND** (ATH-Q1-EX) | 決闘用試作機。紙装甲・最速・全部前向き | 900 | アームガン／アームパイル／パイルバンカー |

難易度は ROOKIE / SOLDIER / VETERAN / RED SHOULDER の 4 段階。
AI の反応速度・射撃精度・攻め気だけが変わり、性能面のズルはしていません
（AI もプレイヤーと同じ `PilotInput` を、同じ 60Hz で入力します）。

## プロジェクト構成

```
core/   純 Kotlin の戦闘シミュレーション（Android 非依存 → JVM でテスト可能）
        MathUtil / Arena / MechSpec / Mech / Projectile / Battle / AiPilot / Input
        Layout（HUD・ボタン・メニューの配置。実機で確認しづらいのでテストで担保）
tools/  check_shaders.py（実 GLES3 でシェーダ検証 + HUD が実際に描画されるかの確認）
        run_on_device.sh（実機での起動確認とログ・フレーム統計の収集）
        preview/（Android の GL 呼び出しを LWJGL 経由で実 GLES に橋渡しし、
                 ゲーム本体のレンダラをヘッドレスで動かして PNG を書き出す）
app/    Android + OpenGL ES 3.0 の表示・入力・音
        gl/      シェーダ、メッシュ、動的クアッドバッチ、行列スタック
        render/  AT モデル生成、カメラ、パーティクル、HUD、フォント生成、レンダラ
        ui/      仮想スティック・ボタン、メニュー
        Game.kt  セッション管理（タイトル→戦闘→リザルト）、Audio.kt  合成効果音
```

シミュレーションと描画は完全に分離してあり、`core` は Android の型を一切参照しません。
描画側は `core` の状態を読むだけで、書き戻しません。

## テストと検証状況

* **コミット済みの Gradle ラッパー + `core/build.gradle.kts` で `:core:test` を実行し、26 件すべてパス**。
  角度演算・遮蔽判定・ダッシュ／ジャンプ／しゃがみ／よろけ・ラウンド進行・決定論性
  （同じ種と入力なら同じ試合になる）・ツインスティックのマッピングまで検証しています。
* `app` の Kotlin コードは実 `android.jar`（Robolectric の android-all, API 35）に対して
  型チェック済み（エラー・警告なし）。`AndroidManifest.xml` と全リソース XML の妥当性も確認。
* **シェーダ 5 プログラムすべてを実 OpenGL ES 3 コンテキスト（Mesa llvmpipe, headless EGL）で
  コンパイル・リンク成功**。さらに Kotlin が設定している uniform / attribute 名が
  リンク後のプログラムに実在することも突き合わせ済み（typo は無音で無視されるため）。
  再実行は下記:

  ```bash
  sudo apt-get install -y libegl1 libgles2 libgl1-mesa-dri   # 初回のみ
  LIBGL_ALWAYS_SOFTWARE=1 python3 tools/check_shaders.py
  ```

* **描画の確認は `tools/preview` で行っています。** Android の `android.opengl` を
  デスクトップ GLES に橋渡しするシムを用意してあり、**ゲーム本体のレンダラをそのまま**
  ビルドマシン上で動かして、狙った瞬間（ダッシュ中、着弾、爆発、被撃破）の PNG を
  書き出せます。見た目の調整はすべてこの画を見ながら行いました。

  ```bash
  cd tools/preview && EGL_PLATFORM=surfaceless gradle run   # shots/ に出力
  ```

* **耐久シミュレーション**: 全 16 組み合わせ × 難易度 3 を 3 分ずつ、合計 8,640 秒
  （518,400 フレーム）回して、NaN / 無限大、アリーナ外への脱出、HP・ブースト・弾数の
  範囲外、弾リークがいずれもゼロ。1 フレームあたり 3.3 マイクロ秒（60fps の予算 16.6ms の
  約 0.02%）で、シミュレーション自体が端末の負荷になることはありません。
  縮小版を `SoakTest` としてテストに常設しています。
* AI 同士の総当たり（4 機体 × 4 機体 × 難易度 3 × 9 戦）でバランスを確認し、
  自爆ダメージの除去、AI の思考レートを 60Hz に固定（プレイヤーと同条件化）、
  砲戦型の強化などを行いました。ミラーマッチはほぼ五分に収束しています。
  **STANDING TORTOISE は AI に持たせると依然として最弱**で、距離を維持できる
  人間向けの上級機という位置づけです。
* **APK のビルドは GitHub Actions 上で成功**（`.github/workflows/android.yml`）。
  `:core:test`、シェーダ検証、`:app:assembleDebug` が全て通り、949KB の
  `app-debug.apk` が成果物として出ています。`processDebugResources`（aapt2）も
  通っているので、マニフェスト・テーマ・アダプティブアイコンも実物の AGP に受理済みです。
  なお開発を行ったサンドボックス自体からは `dl.google.com` が egress ポリシーで
  ブロックされているためビルドできず、CI 側で担保しています。

* したがって **実機での描画・音・タッチ操作は未確認**です。ここまでで潰してあるのは
  「ロジックの正しさ（テスト・耐久シミュレーション）」「Android API の使い方（型チェック）」
  「XML の妥当性」「シェーダのコンパイルとリンク」「`:core` の実ビルド」まで。
  残るのは、GL が実際に描いた絵、音の鳴り、タッチの手触り、実機のフレームレートです。
