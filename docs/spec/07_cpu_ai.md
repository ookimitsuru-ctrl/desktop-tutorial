# 07 CPU AI

## 7.1 設計目標

1. **人間らしく、公正に**: CPU は「人間と同じ入力」を「人間と同じ制約（反応時間・入力精度）」で行う。現在フレームのプレイヤー入力を読む「入力読み」は **禁止**。
2. **負け方が学べる**: 低レベルの CPU は分かりやすい隙を見せ、高レベルの CPU はプレイヤーの癖を学習して突いてくる。
3. **キャラらしさ**: 同じAIエンジンを、キャラごとの「プレイブック」（データ）で個性付けする。
4. **決定論**: AI はシミュレーション状態と AI 専用乱数のみに依存する。同じシード・同じ状況なら同じ判断をする（自動対戦によるバランス検証のため）。
5. **軽量**: 1体あたり 1Tick ≤ 0.5ms（最低ティア端末）。

## 7.2 全体構成

```
           ┌─────────────── AIController（プレイヤー枠1つにつき1つ）──────────────┐
SimState → │ Perception → Situation → TacticSelector → ActionPlanner → InputSequencer │ → InputFrame
           │   (知覚)       (状況分類)     (戦術選択)        (行動計画)       (入力生成)    │
           │        ↑                         ↑                                       │
           │   ObservationHistory       Playbook(JSON) + Difficulty + Adaptation      │
           └──────────────────────────────────────────────────────────────────────────┘
```

- AI はシミュレーションの外側に置き、**通常のプレイヤーと同じ `InputFrame` を出力する**。シミュレーションは入力の出所（人/AI/リプレイ/ネット）を区別しない。
- AI は毎 Tick、シミュレーション状態の **読み取り専用ビュー** を受け取る。

## 7.3 各層の仕様

### 7.3.1 Perception（知覚）

- 相手の状態（状態ID、技ID、状態内経過フレーム、位置）を毎 Tick `ObservationHistory`（直近 60F）に記録する。
- 判断に使う相手の情報は **`reaction_frames` 前の観測** に限定する（例: Lv5 は 16F 前の相手を見て判断）。
  - 例外: 自分自身の状態、および「既に確定した事実」（自分のガード/ヒット結果による有利フレーム）は即時に知ってよい（人間も自分の技がガードされたことは即座に分かる、という扱い）。
- 相手が技を出したことを知覚した時点で、その技のデータ（段・発生・追尾）を参照してよい（人間が「見て分かる」ことに相当）。ただし、**発生が `reaction_frames` 以下の技には反応できない**（物理的に不可能）。

### 7.3.2 Situation（状況分類）

毎 Tick、以下の特徴量を算出する。

| 特徴量 | 値 |
|---|---|
| 距離帯 | 密着（< 0.9m）/ 近（0.9〜1.5m）/ 中（1.5〜2.3m）/ 遠（> 2.3m） |
| フレーム状況 | 自分有利（値）/ 五分 / 自分不利（値）/ 確定反撃チャンス（相手の残り硬直 ≥ 自分の最速技） |
| 相手状態 | 立ち / しゃがみ / 攻撃中（技ID・段・経過）/ ダウン（向き）/ 浮き / よろけ / 背向け / 構え |
| 位置 | 自分の背後の境界までの距離と種類、相手の背後の境界までの距離と種類 |
| 試合状況 | 体力差、残り時間、ラウンドカウント |

### 7.3.3 TacticSelector（戦術選択）

状況ごとに候補となる「戦術」を列挙し、効用スコアで重み付き抽選する（最高スコアを常に選ぶのではなく、ソフトマックス抽選。温度は難易度で変える）。

| 状況 | 戦術候補 |
|---|---|
| 中〜遠距離・五分 | 間合い調整（前後歩き・ダッシュ）、差し込み（リーチのある中段）、横移動、様子見（ガード） |
| 近距離・五分 | 最速技で牽制、中段、下段、投げ、回避、ガード |
| 自分有利 | 打撃の二択（中/下）、投げ、有利継続の技、様子見（暴れ潰し）|
| 自分不利 | ガード（立ち/しゃがみ）、回避、最速技で暴れ、バックダッシュ |
| 確定反撃チャンス | 反撃テーブル（§7.4）から最大期待値の技 |
| 相手ダウン | 起き攻め（中段/下段/投げの重ね、様子見）、ダウン攻撃 |
| 相手浮き | コンボルート選択（`combos.json`） |
| 相手よろけ/崩れ | 確定追撃 |
| 自分ダウン | 受け身の種類、起き上がり動作の選択 |
| 被投げ | 投げ抜けの方向選択（§7.6） |
| 縁際 | 相手を縁へ押す技（吹き飛び・押し戻し大）を加点、自分が縁を背負っている時は横移動・位置入れ替え投げを加点 |

**効用スコア** = プレイブックの基本重み × 状況補正 × 難易度補正 × 適応補正（§7.7）

### 7.3.4 ActionPlanner（行動計画）

- 選んだ戦術を具体的な「行動」（技ID、移動、ガード継続時間など）に変換する。
- 防御行動: 相手の攻撃を知覚した場合、その段に対して正しいガード（上段→しゃがみ or 立ちガード、中段→立ちガード、下段→しゃがみガード、直線→回避も可）を `guard_accuracy` の確率で選ぶ。失敗時は「予想」（適応データの段の比率）でガードする。
- 攻撃行動: 技の `reach` と現在距離を比較し、届かない技は選ばない（Lv1〜2 は 20% の確率で届かない技も選ぶ＝空振りの隙を見せる）。

### 7.3.5 InputSequencer（入力生成）

- 行動を **フレーム単位の入力列** に変換して再生する（例: `46P` → F0: 4, F2: 6, F3: 6+P）。人間と同様にコマンド判定（[02 §2.3.3](02_combat_system.md)）を通るので、AI 専用の「技を直接出す」経路は存在しない。
- **入力精度**: 難易度に応じて、連携の入力タイミングを遅らせる/早めるブレ、コンボの途中で入力を外す確率（`combo_drop_rate`）を持つ。
- ジャスト入力は `just_frame_rate` の確率で成功させる。

## 7.4 反撃テーブル（事前計算）

- データ読み込み時に、キャラごとに「相手の不利フレーム n（n = 10〜30）× 距離帯」に対する **最大期待ダメージの確定反撃** を算出してキャッシュする。
  - 候補: 発生 ≤ n かつ reach ≥ 距離の技。浮かせ技は `combos.json` の該当始動コンボの期待ダメージで評価。
- トレーニングの「最速の確定反撃技」ダミーもこのテーブルを使う。

## 7.5 難易度（CPU レベル 1〜8）

| Lv | 反応 `reaction_frames` | ガード正解率 | 確定反撃実行率 | 投げ抜け（読み） | 回避の使用 | コンボ成功率 | 攻撃性 | 適応学習 | 抽選温度 |
|---|---|---|---|---|---|---|---|---|---|
| 1 | 30F | 30% | 10% | 5% | なし | 50% | 低 | なし | 高（ランダム寄り） |
| 2 | 26F | 45% | 25% | 10% | ごく稀 | 60% | 低 | なし | 高 |
| 3 | 22F | 55% | 40% | 20% | 稀 | 70% | 中 | なし | 中 |
| 4 | 19F | 65% | 55% | 30% | 時々 | 80% | 中 | 弱 | 中 |
| 5 | 16F | 75% | 70% | 40% | 時々 | 88% | 中 | 弱 | 中 |
| 6 | 14F | 82% | 82% | 50% | 適切 | 93% | 高 | 中 | 低 |
| 7 | 12F | 88% | 90% | 60% | 適切 | 97% | 高 | 中 | 低 |
| 8 | 10F | 93% | 97% | 70%（読み込み） | 適切 | 99% | 高 | 強 | 低 |
| ボス | 9F | 95% | 100% | 75%（読み込み） | 適切 | 100% | 最高 | 最強 | 最低 |

- 「投げ抜け」の率は、正しい方向を入力する確率。Lv6 以上は適応データ（プレイヤーが使う投げの方向の頻度）で方向を選ぶため、実効率はプレイヤーの癖によって上下する。
- Lv1〜3 は「明らかな隙」をわざと作る行動（届かない技の空振り、不利フレームでの大技）を一定確率で行う。

## 7.6 投げ抜け・受け身・起き上がりの選択

- 投げ抜け: 受付期間中に、方向を最大2種類入力する（人間と同じ制約）。方向の選択は「プレイヤーの過去の投げ方向の頻度（適応データ）」と「キャラのプレイブックの既定分布」の混合。
- 受け身: Lv3 以上は原則受け身を取る。方向はランダム（重み: その場 40%、横 40%、後ろ 20%）、適応データでプレイヤーの起き攻めに合わせて調整。
- 起き上がり: プレイヤーのダウン攻撃使用頻度が高ければ横転、起き攻めの打撃が多ければ寝っぱなし→起き上がり攻撃を混ぜる、など。

## 7.7 適応学習（プレイヤーの癖の学習）

試合中（およびアーケードの連戦を通して）、プレイヤーの行動頻度をカウントする。

| 観測項目 | 内容 | AIの対策 |
|---|---|---|
| 不利時の行動 | ガード / 暴れ（技）/ 回避 / バックダッシュ の比率 | 暴れが多ければ有利時に「様子見→確定反撃」、ガードが多ければ投げを増やす |
| 有利時の行動 | 中段 / 下段 / 投げ / 様子見 の比率 | 投げが多ければ投げ抜けの方向を合わせる、下段が多ければしゃがみガードを増やす |
| 投げの方向 | N / 4 / 6 / 2 の頻度 | 投げ抜けの方向選択に反映 |
| 起き上がり | 受け身の種類、起き上がり動作の比率 | 起き攻めの選択に反映 |
| 回避の頻度 | 回避の使用率 | 回転技の使用率を上げる |
| よく使う技 | 上位5技 | その技の対策行動（ガード方向、回避、確定反撃）を優先 |

- 各カウントは指数移動平均（減衰率 0.97 / 観測ごと）。Lv に応じた「学習強度」で効用スコアに反映する（Lv4: 0.2、Lv6: 0.5、Lv8: 0.8、ボス: 1.0）。
- 学習データはアーケード1周の間保持し、終了時に破棄する（セーブしない）。

## 7.8 ボスAI（玄斎）

- 通常の AI に加えて「当て身読み」を持つ: プレイヤーが「有利時に打撃を出す」頻度が高いほど、自分が不利なときに当て身（`4P+K` / `1P+K`）を選ぶ。プレイヤーの打撃の段の傾向（上中 or 下）で当て身の種類を選ぶ。
- 1ラウンド目は様子見（学習期間）多め、2ラウンド目以降に学習結果を強く使う。
- 体力が 30% 以下になると攻撃性が上がる（「本気」演出として羽織を脱ぐ等の見た目の変化 — 任意）。
- 公正性の制約は通常AIと同じ（反応時間 9F、入力読み禁止）。

## 7.9 自動対戦によるバランス検証

- ヘッドレスのシミュレーション専用ランナー（描画なし）で、CPU Lv8 同士の対戦を高速に実行する（目標: 1試合 < 1秒、デスクトップ CI 環境）。
- **全組み合わせ**（9キャラ × 9キャラ、ミラー含む）× **200試合**（異なるシード、ステージは `arena` 固定 + 全ステージ混合の2種）を実行し、以下をレポートする。

| 指標 | 合格基準 |
|---|---|
| 勝率マトリクス | 全組み合わせで 40〜60%（[01 Q15](01_vision_and_scope.md)） |
| 平均ラウンド時間 | 20〜35秒 |
| リングアウト決着率 | オープンステージで 15〜35% |
| 最大コンボダメージ（観測） | ≤ 480 |
| 技の使用率 | 単一技が全行動の 25% を超えない |
| 投げの成功率 | 20〜45% |
| 決定論 | 同じシードの再実行で全試合の結果・チェックサムが一致 |

- 出力: `reports/balance/<date>/matrix.csv`、`summary.md`（基準外の項目を強調）。CI で夜間（またはバランス調整PRごと）に実行する。
- **注意**: AI 同士の勝率はあくまで指標であり、AI が苦手な戦術（例: 当て身の読み）の強さは反映されにくい。最終判断は人間のプレイで行う。

## 7.10 プレイブック（キャラ別AIデータ）

`data/characters/<id>/ai_playbook.json`（[12 §12.7](12_data_formats.md)）に以下を定義する。

- 距離帯ごとの戦術の基本重み
- 牽制技リスト、差し込み技リスト、有利時の二択セット（中段候補・下段候補・投げ候補）
- 起き攻めセット
- 縁際で優先する技（リングアウト狙い）
- 固有システムの使い方（例: ビョルンの連続投げの段の選び方、ラヴィの構え移行の頻度、玄斎の当て身頻度）
- 性格パラメータ: 攻撃性、慎重さ、投げ好き度、回避好き度
