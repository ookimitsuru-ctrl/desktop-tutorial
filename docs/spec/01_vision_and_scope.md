# 01 ビジョンとスコープ

## 1.1 コンセプト

**ワンライン**: 「指先で、間合いと1フレームを読む。」

**エレベーターピッチ**:
世界中の実在武術の使い手が、謎の財団が主催する国際大会「RINGBOUND（世界環闘大会）」のリングで拳を交える。
ボタンは P・K・G の3つだけ。ゲージも必殺技演出もない。あるのは上段・中段・下段、投げ、横移動、そして1フレーム単位の有利不利。
リングの縁は常に死の淵であり、どれだけ体力が残っていてもリングアウトすれば負け。
スマートフォンのタッチ操作でも、ゲームパッドでも、同じ読み合いを同じ精度で味わえる、正統派3D格闘ゲーム。

## 1.2 デザインピラー

| # | ピラー | 意味 | 具体的な守り方 |
|---|---|---|---|
| P1 | **読み合いの純度** | 勝敗は「読み」と「判断」で決まる | ゲージ・オート連打コンボ・ランダム要素なし。三すくみ（打撃＞投げ＞ガード＞打撃）＋回避（直線技に勝ち、回転技と投げに負ける）を全キャラ共通ルールとして厳密に運用 |
| P2 | **手触り** | 押した瞬間に応える、当てた瞬間に気持ちいい | 入力遅延予算（§1.6）、ヒットストップ、カメラシェイク、多層SE、振動。60fps 未満は「バグ」扱い |
| P3 | **タッチでも本格** | スマホ操作が「妥協版」にならない | 格闘ゲーム専用設計のタッチUI（[03](03_controls_and_input.md)）。同時押し・フリック回避・ローリング入力・配置カスタム |
| P4 | **美しく、軽く** | ミドルレンジ端末でも美しい | スタイライズド寄りのPBR、強いリムライト、明快なシルエット。品質プリセット4段階 |
| P5 | **学べる** | 誰でも「なぜ負けたか」が分かる | チュートリアル12課、フレーム表示付きトレーニング、確定反撃練習、技トライアル、CPUの癖学習 |

## 1.3 ターゲットプレイヤー

- **主対象**: 3D格闘ゲーム経験者（ゲームセンター世代〜家庭用プレイヤー）で、スマホでも本格的な対戦を遊びたい人。
- **副対象**: 格闘ゲーム初心者。3ボタンの分かりやすさと充実したチュートリアルで入門させる。
- **プレイ環境の想定**: 通勤中のスマホ単体（タッチ）、自宅でのBluetoothゲームパッド接続、友人との1台2コントローラー対戦。

## 1.4 「バーチャファイター風」の解釈

依頼者の要望「バーチャファイター風」は、**ジャンルとゲームメカニクスの方向性**として解釈する。特定作品の再現は行わない。

### 採り入れる（ジャンル共通のメカニクス）

- 3ボタン（P/K/G）＋方向入力という簡潔な操作体系。ガードはボタンで行う
- 上段・中段・下段、立ちガード／しゃがみガードの明快な関係
- 打撃・投げ・ガードの三すくみ、投げ抜け
- 横移動（回避）と、直線技／半回転技／全回転技の関係
- リングアウト、壁、柵、破壊可能な壁
- ダウン攻防（ダウン攻撃、受け身、起き上がり攻撃）
- 実在する武術をベースにした、リアル寄りで重みのあるモーション
- 体力が少なく1ミスが重い、短いラウンド
- 有利不利フレームを中心とした攻防、トレーニングでのフレーム表示

### 採り入れない（既存作品固有の表現）

- 既存作品のタイトル、キャラクター（名前・外見・設定・流派の組み合わせ）、技名、ステージ、BGM、SE、ボイス、アナウンス文言、UIレイアウト、ロゴ、フォント、カラースキーム
- 既存キャラクターを想起させる「〇〇の代わり」というキャラクター設計（例: 銀色の金属質ボス、特定作品の主人公を思わせる組み合わせ）
- 詳細は [18 法務](18_legal_and_assets.md) の禁止リストに従う

## 1.6 品質基準（Quality Bar）— 全て計測可能な形で定義する

| ID | 項目 | 合格基準 | 計測方法 |
|---|---|---|---|
| Q1 | フレームレート | 推奨ティア端末で対戦中 **平均60fps・1%Low ≥ 57fps**。最低ティア端末（Lowプリセット）で平均 ≥ 59fps | 実機で30分連続対戦（CPU vs CPU）し、フレームタイムログを取得（[13](13_performance.md)） |
| Q2 | サーマル | 30分連続で Q1 を維持（端末温度上昇によるスロットリング後も） | 同上 |
| Q3 | 入力遅延（ゲーム内） | 入力イベント受信から、その入力を反映した画像の描画コマンド発行まで **≤ 2フレーム** | 内部タイムスタンプログ |
| Q4 | 入力遅延（体感） | タッチ→画面反映 **≤ 100ms**、ゲームパッド（有線/USB）→画面反映 **≤ 83ms**（推奨ティア） | 240fps ハイスピード撮影 |
| Q5 | 入力取りこぼし | 1フレーム内の押して離す操作、2ボタン同時押しを **100%** 検出 | 自動テスト＋手動テスト |
| Q6 | フレームデータ正確性 | 全技の発生・持続・硬直・ガード/ヒット/カウンター時有利が **データ定義と100%一致** | CI の自動検証（[15](15_qa_and_testing.md)） |
| Q7 | 決定論 | 同一入力列 → 同一結果（全状態のチェックサム一致）。100シード × 10万フレーム | CI |
| Q8 | 安定性 | クラッシュ・フリーズ 0 件（2時間ソークテスト × 3端末） | 実機テスト |
| Q9 | 起動時間 | コールドスタート→タイトル操作可能まで ≤ 5秒（推奨ティア） | 実機計測 |
| Q10 | ロード時間 | キャラ/ステージ決定→対戦開始 ≤ 4秒（推奨ティア）、≤ 8秒（最低ティア） | 実機計測 |
| Q11 | ヒッチ | 対戦中の 50ms 超のフレーム落ち **0回/試合**（初回シェーダーコンパイル含む） | フレームタイムログ |
| Q12 | 容量 | APK ≤ 250MB、メモリ使用量 ≤ 1.0GB（最低ティア） | ビルド成果物 / `dumpsys meminfo` |
| Q13 | 分かりやすさ | 格闘ゲーム未経験のテスターがチュートリアル1〜6課を **30分以内** に修了 | ユーザーテスト |
| Q14 | タッチ誤入力 | 技トライアル基本課題での「意図しない技の暴発」率 ≤ 2% | トライアルのログ集計 |
| Q15 | バランス | 最高難度CPU同士の自動対戦で、全組み合わせの勝率が **40〜60%** の範囲 | 自動対戦（[07 §7.9](07_cpu_ai.md)） |

## 1.7 体験目標（1試合の流れの理想像）

- 1ラウンド平均 **20〜35秒**。1試合（2本先取）平均 **1分30秒〜2分30秒**。
- 1ラウンドあたり「大きな読み勝ち（浮かせ・投げ・カウンター大技）」が **3〜5回** 発生すれば決着する体力設計。
- 体力満タンからでも、リングアウトか、2〜3回の大きな読み負けで負ける緊張感。
- 負けたプレイヤーが「今のは中段を読まれた」「回避すべきだった」と **言語化できる** こと（ヒット種別表示・リプレイ・トレーニングの充実で担保）。

## 1.8 世界観（最小限）

- 舞台は現代。架空の国際組織「**環（たまき）財団**」が、世界各地の伝統武術・実戦武術の使い手を招待して開く大会「RINGBOUND」。
- 大会のリングは世界各地の「境界」の地（港、竹林、砦跡、砂漠の遺跡、摩天楼、古寺、川、闘技場）に設営される。
- 物語はキャラクターごとの短い動機（アーケードのオープニング/エンディング各1枚絵＋テキスト200字程度）で語る。重厚なストーリーは作らない。
