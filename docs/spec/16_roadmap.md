# 16 ロードマップ

## 16.1 進め方の原則

1. **遊べる状態を保ち続ける**: 各マイルストーンの終わりには、必ずオーナーの端末にインストールして遊べる APK がある。
2. **縦に切る**: 全キャラを少しずつ作るのではなく、まず2キャラ・2ステージを製品品質まで仕上げ（M3）、その品質を基準に横へ展開する（M4）。
3. **ルールを先に固める**: 見た目より先に、灰色の箱（マネキン）で全ルールを実装・テストする（M1〜M2）。
4. **各作業は小さく**: 1つの作業（コミット/PR）は「1つの機能＋そのテスト」。CI が緑のまま積み上げる。

## 16.3 各マイルストーンの作業と完了条件

### M0 基盤構築

**作業**
1. `tools/versions.env`（Godot・テンプレート・GUT・Blender・Android SDK の各バージョン）を作成。
2. Godot プロジェクト作成、[11 §11.3](11_technical_architecture.md) のプロジェクト設定、ディレクトリ構成、autoload の雛形。
3. GUT を導入し、サンプルテスト1件。
4. `.github/workflows/ci.yml`: インポート → リンター（雛形）→ GUT → Android デバッグ APK エクスポート → 成果物アップロード。
5. テストシーン: 回転する立方体、FPS 表示、タッチ点の可視化（マルチタッチ）、ゲームパッド入力表示、振動テストボタン、端末情報（GPU・レンダラ・解像度・リフレッシュレート）表示。
6. `docs/spec/CHANGELOG.md`、`docs/ASSET_LEDGER.md`、`docs/DEVLOG.md`、`docs/checklists/M0.md` を作成。
7. Git LFS の設定（[17 §17.6](17_agent_rules.md)）。

**完了条件**
- [ ] CI が緑で、Artifacts からデバッグ APK を取得できる
- [ ] （オーナー）APK をインストールし、テストシーンが 60fps で表示され、タッチとゲームパッドが反応する

### M1 コアシミュレーション

**作業**
1. 固定小数点（`FP`、ベクトル、三角関数テーブル生成、atan2、sqrt）＋テスト。
2. 乱数（PCG32）、チェックサム（FNV-1a）＋テスト。
3. `InputFrame`、入力履歴、`InputHub`（キーボード・ゲームパッド・簡易タッチ）。
4. コマンドパーサー（[02 §2.3](02_combat_system.md) の猶予・遡及同時押し・優先順位）＋網羅テスト。
5. `SimWorld` の骨格、Tick のフェーズ（[11 §11.7](11_technical_architecture.md)）、スナップショット＋往復テスト。
6. ファイター状態: 立ち・歩き・しゃがみ・ダッシュ・バックダッシュ・ガード・攻撃・ガード硬直・ヒット硬直。
7. 判定（カプセル）・段と姿勢のルール・硬直の自動算出・ヒットストップ・体力・ラウンド・タイマー。
8. マネキン（カプセルの組み合わせのキャラ。ボーン構成は本番と同じ）と、手書きの判定データでの仮の技 10種（`P`, `P,P`, `6P`, `3P`, `2P`, `K`, `3K`, `2K`, `立ちP`, `P+G`は M2）。
9. 簡易カメラ（[09 §9.8](09_art_animation_camera_vfx.md) の基本パラメータ）、簡易 HUD（体力・時間・ラウンド）。
10. トレーニングの骨格: ダミー動作（立ち・しゃがみ・ガード）、フレームデータ表示（実測）、判定表示、位置リセット。
11. フレームデータ自動検証（[15 §15.2](15_qa_and_testing.md)）と決定論テスト（[15 §15.3](15_qa_and_testing.md)）を CI に組み込む。
12. シミュレーション層のリンターを有効化。

**完了条件**
- [ ] 2体のマネキンで対戦でき、ラウンド制で決着がつく
- [ ] 全仮技のフレームデータ実測がデータと一致（CI）
- [ ] 決定論テスト（再実行・往復）が緑
- [ ] 1 Tick のシミュレーション時間をヘッドレスベンチマークで記録
- [ ] （オーナー）ゲームパッドとタッチで基本技が出る

### M2 戦闘システム完成

**作業**（各項目に対応する単体/結合テストを必ず書く）

2. 横移動（回避）と追尾（直線/半回転/全回転）、回避ガード、回避攻撃、回避成功ボーナス
3. しゃがみ移行・立ち上がり・立ち途中技、手前回避との曖昧さ解決
4. 走り、走り技、走り投げ
5. カウンターヒット、よろけ（レバガチャ）、崩れ、相打ち、側面/背面ヒット、背向け
6. 浮き・空中コンボ（重力・再浮き減衰・補正・強制落下）
7. ダウン（4向き）、受け身、起き上がり各種、ダウン攻撃
8. 境界: open/fence/wall/breakable、壁ヒット/壁張り付き、リングアウト、縁際の停止、`camera_side`
9. 連携（chain・ディレイ）、ジャスト入力、溜め、構えの枠組み、当て身/受け流しの枠組み

13. リプレイの記録・再生、ゴールデンリプレイ 10本

**完了条件**

## 16.4 リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| スクリプト生成の 3D モデルの見た目が目標品質に届かない | 見た目の品質 | スケルトン・ファイル規約を固定し、プランB（人間のアーティスト / 商用可の 3D 生成）へ差し替え可能にしておく（[09 §9.4.3](09_art_animation_camera_vfx.md)）。M3 のオーナー確認で判断 |
| 数値で書いたアニメーションが硬い | 手触り・見た目 | ポーズライブラリ、イージングの規則、Movie Maker による反復レビュー。必要に応じてモーションキャプチャ（動画からの姿勢推定等、ライセンスを確認したもの）でキーポーズの参考を取る |
| Android の性能・発熱 | 60fps | M0 で端末の実力を測り、M3 で予算を確定。プリセットと解像度スケーリング |
| タッチ操作の手触り | 体験の核 | M1〜M2 で早期にオーナーの実機フィードバック。設定項目を豊富に |
| 決定論の破れ | リプレイ・オンライン | M1 から決定論テストを CI に。浮動小数点禁止のリンター |
| 固定したエンジン版に本書記載の機能がない | 実装の停滞 | 自前実装に置き換え、CHANGELOG に記録（[11 §11.1](11_technical_architecture.md)） |
| コンテナ環境に GPU・実機がない | 見た目の確認 | ヘッドレステスト＋ソフトウェアレンダリング（Xvfb＋Mesa の OpenGL）での Movie Maker 書き出し＋オーナーの実機チェックリスト |
| スコープの肥大 | 完成しない | [README §4](README.md) の優先順位。M3 で品質基準を固めてから横展開 |
| 素材のライセンス問題 | 公開不可 | アセット台帳の徹底、CC0 優先（[18](18_legal_and_assets.md)） |

## 16.5 最初の一歩（M0 の具体的な着手手順）

1. `tools/versions.env` を作成し、Godot の最新 4.x stable パッチ版の番号を確認して記入する。
2. ローカル（コンテナ）に Godot（Linux x86_64）とエクスポートテンプレートをダウンロードし、`godot --headless --version` で動作を確認する。
3. `project.godot` を作成し、プロジェクト設定を反映、`godot --headless --import` が通ることを確認する。
4. GUT を `addons/gut/` に配置し、`godot --headless -s addons/gut/gut_cmdln.gd -gdir=res://tests -gexit` でサンプルテストを実行する。
5. Android SDK（cmdline-tools）と JDK 17 を導入し、デバッグキーストアを生成して、ローカルで `--export-debug` が通ることを確認する（コンテナで不可能な場合は CI 上で確認する）。
6. CI ワークフローを作成して push し、APK が Artifacts に出ることを確認する。
7. `docs/checklists/M0.md` にオーナー向けのインストール手順と確認項目を書き、M0 完了を報告する。
