# 13 パフォーマンス

## 13.1 原則

- **60fps は仕様である**。60fps を割る状況はバグとして扱い、機能追加より優先して直す。
- 最適化は計測してから行う。全ての最適化は「変更前後の計測値」をコミットメッセージか `docs/DEVLOG.md` に残す。
- 予算はプリセットごとに定め、超えた場合は CI（ヘッドレスで測れるもの）または実機チェックリストで検出する。

## 13.2 端末ティア

| ティア | 目安となる SoC 世代 | RAM | 既定プリセット | 目標 |
|---|---|---|---|---|
| 最低 | 2020〜2021年のミドルレンジ（例: Snapdragon 7xx 世代前半、Dimensity 700〜800 世代、Helio G9x 世代） | 4GB | Low | 平均 ≥ 59fps |
| 中 | 2022〜2023年のミドルハイ（例: Snapdragon 7 Gen 1〜2、Tensor G1〜G2、Exynos 1380 世代） | 6GB | Medium | 平均 60fps、1%Low ≥ 57 |
| 推奨 | 2022年以降のハイエンド（例: Snapdragon 8 Gen 1 以降、Dimensity 9000 以降） | 8GB+ | High | 平均 60fps、1%Low ≥ 58 |
| 最上位 | 2024年以降のフラッグシップ | 12GB+ | Ultra | 平均 60fps、1%Low ≥ 58、30分後も維持 |

- **自動判定**: 初回起動時に、GPU 名・RAM・Vulkan 対応の有無から暫定ティアを決め、タイトル画面の背景シーンで 3秒間のベンチマーク（GPU フレームタイム計測）を行い確定する。結果は設定に保存し、オプションで変更可能。
- Compatibility（GLES3）レンダラで動作している場合は最大 Medium。

## 13.6 メモリ・容量

| 項目 | 上限 |
|---|---|
| 実行時メモリ（PSS、最低ティア） | ≤ 1.0GB |
| APK サイズ | ≤ 250MB（Google Play 公開時に 200MB を超える場合は Play Asset Delivery を検討） |
| リプレイ 1件 | ≤ 20KB |
| セーブデータ合計 | ≤ 5MB（リプレイ除く） |

- 試合中はキャラ2体＋ステージ1つ分のアセットのみ常駐。キャラ選択画面では全キャラの LOD2 モデルのみ常駐し、決定後に本番用 LOD を読み込む。

## 13.7 ヒッチ（カクつき）対策 — 必須

| 原因 | 対策 |
|---|---|
| シェーダーのコンパイル | 使用する全マテリアル×メッシュ種別×ライト条件の組み合わせを、VS 画面中にオフスクリーンで1回ずつ描画して **ウォームアップ**。エンジンのパイプラインキャッシュ・シェーダー事前コンパイル機能（エンジン対応版で利用可能なもの）を有効化 |
| リソース読み込み | 試合開始前に全て読み込む（試合中に `load()` しない）。読み込みは `ResourceLoader.load_threaded_request` で非同期 |
| ノード生成 | VFX・音・UI 要素はプール。試合中の `instantiate()` / `queue_free()` を禁止 |
| メモリ確保 | シミュレーションの配列は事前確保して再利用。文字列の連結・フォーマットを毎フレーム行わない（HUD の数値は変化時のみ更新） |
| ガベージ | GDScript は参照カウントだが、一時的な Array/Dictionary の大量生成は避ける |
| オーディオ | ストリーム BGM は試合前に再生開始、SE はプリロード済みのストリームのみ |

- 合格基準: 対戦中に 50ms を超えるフレームが **0回/試合**（Q11）。

## 13.8 サーマル・電力

- 30分連続対戦で性能を維持するため、GPU に余裕（推奨ティアで GPU 使用率 75% 以下）を残す。
- 端末温度の上昇を検出した場合（Android の熱状態 API を、エンジン機能またはプラグイン経由で取得できる場合）は、描画解像度を自動で 1段階下げる（シミュレーションには影響しない）。
- 省電力モード（[08 §8.7](08_ui_ux.md)）: Low 強制・解像度 60%。
- メニュー画面では 3D 背景の更新を 30fps に落とす（入力の応答性は維持）。

## 13.9 計測方法

| 計測 | 方法 |
|---|---|
| フレームタイム | ゲーム内のフレームタイムログ（デバッグビルド: 毎フレームの CPU 時間・描画時間・Tick 数を `user://logs/frametime_*.csv` に出力）、`adb shell dumpsys gfxinfo` |
| GPU | Android GPU Inspector（対応端末）、各社 GPU プロファイラ |
| システム | Perfetto トレース（`adb shell perfetto`）でスレッドのスケジューリング・サーマルを確認 |
| メモリ | `adb shell dumpsys meminfo io.github.ookimitsuru.ringbound` |
| エンジン内 | Godot のプロファイラ（リモートデバッグ）、`Performance` シングルトンのモニター |
| 入力遅延 | 240fps のハイスピード撮影（画面とタッチの指/ボタンを同時に撮影し、押下から画面変化までのフレーム数を数える）＋ゲーム内の内部計測 |
| CI（ヘッドレス） | シミュレーション 10万 Tick のベンチマーク（1 Tick の平均・最大時間）、AI のベンチマーク。前回比 +20% で警告 |

## 13.10 起動とロード

| 項目 | 目標（推奨ティア） | 対策 |
|---|---|---|
| コールドスタート → タイトル操作可能 | ≤ 5秒 | 起動シーンを最小にし、DataDB の読み込みをバックグラウンドで実行。タイトル背景は遅延読み込み |
| キャラ/ステージ決定 → 対戦開始 | ≤ 4秒（最低ティア ≤ 8秒） | VS 画面中に並列読み込み＋ウォームアップ |
| ラウンド間 | 0秒（ロードなし） | |
| 再戦 | ≤ 1秒 | アセットを再利用 |
