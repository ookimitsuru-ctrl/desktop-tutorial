# 03 操作と入力処理

## 3.1 対応入力デバイス

| デバイス | 位置付け | 備考 |
|---|---|---|
| タッチスクリーン | **主操作**。格闘ゲーム専用設計 | 1P のみ（1台の画面を2人で触るローカル対戦は非対応） |
| ゲームパッド（Bluetooth / USB） | 完全対応。推奨操作 | Xbox / PlayStation / Switch Pro 互換 / 汎用 Android ゲームパッド。2台接続でローカル2P |
| キーボード | 開発・デスクトップ検証用（Android の物理キーボードでも動作） | P1/P2 の2配置 |

- 1P がタッチ、2P がゲームパッドというローカル対戦も可能とする。
- 入力デバイスは試合中にホットプラグ（接続/切断）されてもクラッシュしないこと。試合中にゲームパッドが切断された場合は即座にポーズメニューを開く。

## 3.2 タッチ操作

### 3.2.1 既定レイアウト（横画面）

```
┌───────────────────────────────────────────────────────────────────────────┐
│ [P1 体力バー ████████████]      45      [████████████ P2 体力バー]   (⏸) │
│                                                                           │
│                                                                           │
│                                                                           │
│                                                         ╭────╮            │
│                                                         │ G  │            │
│        ╭──────╮                                  ╭────╮ ╰────╯ ╭────╮     │
│       │   ●    │  ← フローティング・スティック    │ P  │        │ K  │     │
│        ╰──────╯   （左45%の任意位置に出現）       ╰────╯        ╰────╯     │
│                                                  [投げ]  [P+K]  [K+G]    │
└───────────────────────────────────────────────────────────────────────────┘
```

- 右側の主ボタン3つ（P・K・G）は三角形に配置し、**隣り合う2ボタンの間を親指の腹で押すと同時押し** になる（後述のコードゾーン）。
- 下段の小ボタンは同時押しマクロ（プリセットにより表示/非表示）。

### 3.2.2 スティック

| 項目 | 既定値 | 設定範囲 |
|---|---|---|
| 方式 | **フローティング**（画面左 45% の任意の位置に触れた点が中心になる） | フローティング / 固定 |
| 外周半径 | 64dp | 48〜96dp |
| ノブ最大移動 | 64dp（外周まで） | — |
| デッドゾーン | 外周半径の 22% | 10〜40% |
| 方向区分 | 8方向。**上下左右 = 各54°、斜め = 各36°**（斜めの誤入力を減らす） | 斜め幅 30〜45° |
| ヒステリシス | 区分境界で 6°（境界付近でのチャタリング防止） | 0〜10° |
| 追従 | 指がフローティング領域外へ大きく動いた場合、外周半径の 1.6 倍を超えた分だけ中心を指に追従させる | ON/OFF |
| 表示 | 触れていない時は半透明のガイド円を既定位置に表示 | 透明度 0〜100% |

- 方向はスクリーン基準で取得し、シミュレーション側で自分基準（6=相手側）に変換する（[02 §2.3.2](02_combat_system.md)）。
- **フリック判定（タップ入力）**: デッドゾーン外の方向に入り、6F 以内にデッドゾーン内へ戻ったものを「タップ」として扱う。これにより `8` タップ（奥回避）、`2` タップ（手前回避）、`66`（ダッシュ）、`44`（バックダッシュ）を自然に入力できる。
- 指を離した瞬間はニュートラル。

### 3.2.3 ボタン

| 項目 | 既定値 |
|---|---|
| 主ボタン（P / K / G）直径 | 84dp（設定 60〜120dp） |
| 判定領域 | 見た目の **1.2倍**（隣接ボタンと重なる部分はコードゾーンになる） |
| コードゾーン | 隣接する2ボタンの判定領域が重なる部分、および2ボタン中心を結ぶ線分から 18dp 以内を「同時押し領域」とする（P+G、K+G、P+K） |
| ローリング入力 | 指を押したままボタン間を滑らせると、新しく入ったボタンが「押された」扱いになる（P を押したまま G へ滑らせる → P+G の同時押し判定猶予 2F 内なら投げ） |
| マクロボタン直径 | 60dp |
| 表示 | 拳/足/盾のアイコン＋文字。押下中は発光＋縮小アニメ（60ms） |
| マルチタッチ | 最大 10 点。スティック 1 点＋ボタン側複数点を同時処理 |

### 3.2.4 プリセット

| プリセット | 内容 | 対象 |
|---|---|---|
| **スタンダード**（既定） | スティック ＋ P/K/G ＋ マクロ [投げ(P+G)] [P+K] [K+G] | 大半のプレイヤー |
| **クラシック** | スティック ＋ P/K/G のみ（同時押しはコードゾーンとローリングで行う） | 上級者 |
| **アシスト** | スタンダード ＋ [回避] ボタン（押すと奥回避、スティック下入れ中は手前回避）＋ オフラインで「投げ抜け簡易化」ON | 初心者 |
| **左利き** | 上記いずれかを左右反転 | 左利き |

### 3.2.5 レイアウト編集

- 全ての要素をドラッグで移動、ピンチまたはスライダーでサイズ変更（70〜140%）、透明度変更（20〜100%）。
- 要素同士の重なり（コードゾーンを除く）と、画面端から 24dp 以内への配置を禁止（ガイド表示で警告）。
- 3スロットまで保存。トレーニング中にポーズメニューから直接編集でき、編集後すぐに試せる。
- 「初期化」で選択中プリセットの既定に戻る。

### 3.2.6 フィードバック

- **振動（ハプティクス）**: 強度設定 0（オフ）〜3。

| イベント | 長さ | 強さ（相対） |
|---|---|---|
| 自分の攻撃がヒット | 20ms | 0.5 |
| 自分の攻撃がカウンターヒット | 35ms | 0.8 |
| 自分の攻撃がガードされた | 10ms | 0.3 |
| 自分が被弾 | 25ms | 0.6 |
| 投げ抜け成功 | 15ms ×2 | 0.5 |
| KO / リングアウト | 80ms | 1.0 |

- **視覚**: ボタン押下の発光、スティックの方向インジケーター（8方向のどれに入っているかを外周に表示）。トレーニングでは入力履歴を表示（§3.6）。

### 3.2.7 Android 固有の配慮

- 没入モード（ナビゲーションバー・ステータスバー非表示）、横画面固定（センサーによる左右反転は許可）、画面スリープ無効（試合中）。
- 戻る操作（戻るボタン・戻るジェスチャー）は **アプリ終了ではなくポーズメニューを開く**（`application/config/quit_on_go_back = false`、`NOTIFICATION_WM_GO_BACK_REQUEST` を処理）。
- ディスプレイカットアウト（パンチホール・ノッチ）とジェスチャー領域を避けるため、UI は `DisplayServer.get_display_safe_area()` の内側に配置し、さらに画面端から 24dp のマージンを取る。
- 一部メーカーの「3本指スクリーンショット」等のジェスチャーと干渉しうるため、オプションの「ヒント」に無効化方法を案内する。
- 画面サイズ 16:9 〜 22:9 に対応。タブレット（4:3 〜 16:10）ではボタンを画面高さ基準で配置する。

## 3.3 ゲームパッド

### 3.3.1 既定配置（Xbox 表記 / PlayStation 表記）

| 入力 | 既定割当 |
|---|---|
| 左スティック / 十字キー | 方向（どちらでも可。スティックのデッドゾーン 0.25、方向区分はタッチと同じ） |
| X / □ | **P** |
| B / ○ | **K** |
| A / × | **G** |
| Y / △ | P+K |
| RB / R1 | P+G（投げ） |
| RT / R2 | K+G |
| LB / L1 | P+K+G |
| LT / L2 | （未割当・ユーザー設定可） |
| Start / Options | ポーズ |
| Back / Share | トレーニング: リセット（位置の初期化） |

- 全ボタン再割当可能。1つのボタンに複数のゲームボタン（マクロ）を割り当てられる。
- ゲームパッド接続時はタッチUIを自動的に非表示にする（画面タッチで再表示）。
- メニューは全てゲームパッドで操作可能（フォーカスナビゲーション）。

### 3.3.2 ローカル2P のデバイス割当

- VS モード開始時に「デバイス割当画面」を表示し、各デバイスでいずれかのボタンを押すと、押した順に P1/P2 に割り当てる。タッチは「画面をタップ」で P1/P2 のどちらかに割り当てられる。
- 割当はキャラ選択画面でも変更可能。

## 3.5 入力処理パイプライン（実装仕様）

### 3.5.1 Godot の設定（必須）

- 起動直後に `Input.use_accumulated_input = false`（入力イベントの結合を禁止し、全イベントを個別に受け取る）。
- `input_devices/pointing/emulate_mouse_from_touch = false`、`input_devices/pointing/emulate_touch_from_mouse = true`（デスクトップでマウスによるタッチ検証を可能にする）。
- 入力処理は autoload `InputHub` の `_input(event)` で受け取る（UI の `Control` に吸われないよう、試合中のタッチ操作レイヤーは独自に処理し、`mouse_filter` を適切に設定する）。

### 3.5.2 処理の流れ

```
[OSイベント] → InputHub._input(event)
    ├─ タッチ:   touch_index ごとに「担当要素（スティック/ボタン/なし）」を割当て、状態を更新
    ├─ パッド:   ボタン押下/解放、軸値を更新
    └─ キー:     押下/解放を更新
    ※ 各イベントで「押された」「離された」をラッチ（次のシミュレーションTickで消費されるまで保持）

[_process 開始時] MatchClock がこの描画フレームで実行する Tick 数 n を決定（通常 1）
    for 各 Tick:
        InputHub.sample(player) → InputFrame（dir=画面基準, held, pressed, released）
            ※ ラッチされた pressed/released は最初の Tick にのみ反映
        Simulation.step([InputFrame P1, InputFrame P2])
[同フレーム内] Presentation.update(sim_state, events) → 描画
```

- **入力から描画まで最大1フレーム**: 入力イベントは各フレームの `_process` より前に Godot がディスパッチするため、受信したフレームでそのままシミュレーションに反映する。
- 1フレーム内で「押して離した」場合も `pressed` を必ず立てる（Q5）。`held` は Tick 時点の実状態。
- タッチの担当割当は「指が最初に触れた位置」で決め、その指が離れるまで変えない（ローリング入力のための例外: ボタン領域内での移動は担当ボタン群を更新する）。

### 3.5.3 方向の量子化

```
入力ベクトル v（スクリーン座標、上=+y）
|v| < deadzone → N
角度 θ = atan2(v.y, v.x)
区分: 右(6) = -27°〜+27°、右上(9) = 27°〜63°、上(8) = 63°〜117° … （上下左右 54° / 斜め 36°）
境界から ±hysteresis 以内なら前フレームの方向を維持
```

- この量子化結果を「画面基準のテンキー方向」として InputFrame に格納する。左右→前後の変換はシミュレーション内で、その Tick 時点の左右関係を使って行う（決定論のため、変換に使う左右関係もシミュレーション状態から決める: 対戦軸とカメラ側ベクトルの外積の符号。カメラ側ベクトルはシミュレーションが保持する「カメラ側」状態で、§[09 カメラ](09_art_animation_camera_vfx.md) の規則に従いシミュレーション内で更新する）。

> **重要**: 「画面上の左右」を描画側のカメラから取ると、ロールバック時や描画遅延で入力解釈がずれる。したがって **「どちらが画面左か」はシミュレーション状態の一部** として決定論的に管理する（`screen_side` 状態）。

### 3.5.4 入力ログ

- 全ての InputFrame はリプレイ・デバッグ用に試合単位で記録する（1F = 2プレイヤー × 2バイト）。
- デバッグビルドでは、入力イベント受信時刻・Tick 時刻・描画提出時刻を記録し、入力遅延（Q3）を自動計測する。

## 3.6 入力表示（トレーニング・リプレイ）

- 画面左端（P1）/右端（P2）に、入力が変化するたびに1行追加する縦リスト（最大 20 行）。
- 各行: 方向アイコン ＋ ボタンアイコン ＋ その入力が続いたフレーム数。
- 成立した技の名前を行の右に表示（技名表示 ON 時）。
- 同時押し判定が成立した場合は2つのボタンアイコンを連結して表示。

## 3.7 アシスト機能（オフライン限定）

| 機能 | 内容 | 既定 |
|---|---|---|
| 投げ抜け簡易化 | 方向に関係なく P+G で通常投げを抜けられる | アシストプリセット時 ON |
| 回避ボタン | 1ボタンで横移動 | アシストプリセット時 ON |
| 受け身自動 | ダウン時に自動でその場受け身（受け身可能な場合） | OFF |
| コマンド猶予拡大 | §2.3.3 の猶予を 1.5倍 | OFF |

- アシストを使用した記録（タイムアタック等）には印を付ける。
