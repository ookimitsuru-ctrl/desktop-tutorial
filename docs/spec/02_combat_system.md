# 02 戦闘システム

本章は本作の心臓部である。**ここに書かれたルールは全キャラクター共通の「物理法則」**であり、キャラクター固有の例外は技データのフラグとして明示的に表現する（暗黙の例外を作らない）。

---

## 2.1 基本パラメータ

| 項目 | 値 | 備考 |
|---|---|---|
| シミュレーション周期 | **60Hz 固定**（1F = 1/60秒） | 描画周期とは独立。描画も60fpsに固定する（[11 §11.5](11_technical_architecture.md)） |
| 体力 | **1000**（全キャラ共通） | キャラ差は体力ではなく「浮きやすさ」「投げ間合い」等で表現 |
| ラウンド数 | 既定 **2本先取**（設定で1〜5本先取） | オンライン/ランク相当は2本先取固定 |
| ラウンド時間 | 既定 **45秒**（設定: 30 / 45 / 60 / 無制限） | 1秒＝60F。ヒットストップ中もタイマーは進む |
| 初期間合い | 両者の中心間距離 **2.40m** | リング中心を通る直線上に配置 |
| 座標単位 | 固定小数点 Q16.16（1.0m = 65536） | float はシミュレーション内で禁止（[11 §11.6](11_technical_architecture.md)） |
| 角度単位 | 16bit 2進角（0〜65535 = 0°〜360°） | sin/cos はビルド時生成の整数テーブル |

## 2.2 座標系・向き・位置関係

- ワールドは Y 上向き、地面は XZ 平面、リング中心が原点。
- 各ファイターの状態: 位置 `(x, z)`、高さ `y`（空中時のみ非0）、向き `facing`（2進角）、速度 `(vx, vy, vz)`。
- **対戦軸**: 自分から相手への水平ベクトル。距離 `dist` は対戦軸の長さ。
- **自動向き補正**: 以下の「自由状態」では毎フレーム `facing` を対戦軸方向へ即時に合わせる。
  - 自由状態 = 立ち、しゃがみ、歩き、ガード（立ち/しゃがみ）、ダッシュ、ステップ回避の終了後、起き上がり完了時
- **技中の向き**: 技の `tracking`（追尾）区間中のみ、1Fあたり最大 `tracking_rate`（既定 6°/F）で対戦軸に向けて回転する。追尾区間外では向きは固定。
- **背向け**: 一部の技・投げの後に「背向け状態」となる。背向け中は `facing = 対戦軸 + 180°` とし、背向け専用技が使える。背向けからはガード不可、`G` 入力で正面に振り向く（振り向き 8F）。
- **相対位置の判定**（攻撃が当たった時の、防御側から見た攻撃者の方向）:

| 区分 | 防御側の正面からの角度 | 効果 |
|---|---|---|
| 正面 | ±60°以内 | 通常 |
| 側面 | 60°〜120° | ガード可能。ヒット時のヒット硬直 +2F、側面投げが発生 |
| 背面 | 120°超 | **ガード不可**。ヒット時ダメージ ×1.10、背後投げが発生 |

## 2.3 入力記法と入力解析

### 2.3.1 記法

| 記法 | 意味 | 例 |
|---|---|---|
| `6` `4` `2` `8` `3` `1` `9` `7` | 自分の向きを基準とした方向（6=相手側） | `6P` 前を入れながらP |
| `N` / `5` | ニュートラル | |
| `P` `K` `G` | ボタン | |
| `X+Y` | 同時押し（猶予 2F） | `P+G` 投げ |
| `X,Y` | 連携（前の技の受付時間内に次を入力） | `P,P,K` |
| `66` / `44` | 素早く2回（ダッシュ/バックダッシュ） | `66K` ダッシュ中K |

| `立ち` | しゃがみから立ち上がる途中（2を離した直後 8F 以内） | `立ちP` |
| `しゃがみ途中` | 2を入れてしゃがむ途中（2入力後 1〜3F） | |
| `回避中` | 横移動の受付区間中 | `回避中P` |
| `背向け` | 背向け状態中 | `背向けK` |
| `構え中` | キャラ固有の構え中 | `獅子構え中P` |
| `ダウン中` / `起き上がり` | ダウン状態の側の入力 | `ダウン中K` |

### 2.3.2 入力フレーム（InputFrame）

各シミュレーションフレームで、各プレイヤーにつき1つの `InputFrame` を生成する。

- `dir`: 1〜9（**画面基準**で入力されたものを、そのフレームの自キャラの左右関係で **自分基準** に変換したもの）
- `held`: P/K/G の押下状態ビット
- `pressed`: そのフレームで新たに押されたボタンのビット（**1フレーム内で押して離した場合も必ず立てる**）
- `released`: そのフレームで離されたボタンのビット

画面基準→自分基準の変換: 画面上で相手が自分の右にいれば「右=6」、左にいれば「左=6」。**「どちらが画面の左か」は描画側のカメラではなく、シミュレーション状態 `cam_dir`（カメラがいる側を示す、対戦軸に垂直な単位ベクトル。更新規則は [09 §9.8.1](09_art_animation_camera_vfx.md)）から決定論的に求める**（`cam_dir` と対戦軸の外積の符号）。上下（8/2）は常に画面上下。**奥=8、手前=2** で固定（カメラは常に横から見ているため）。

### 2.3.3 入力履歴とコマンド判定

- 各プレイヤーにつき直近 **60F** の InputFrame をリングバッファで保持する。
- コマンド判定は「方向の変化イベント」と「ボタン押下イベント」の時系列で行う（フレームごとの方向値の羅列ではなく、方向が変化した瞬間のログ）。
- 判定猶予（全キャラ共通・技データで個別上書き可）:

| 種類 | 猶予 |
|---|---|
| 同時押し `X+Y` | 2つ目のボタンが 1つ目の押下から **2F 以内** |
| `66` / `44` / `88` / `22` | 1回目の押下 → ニュートラル → 2回目の押下 が合計 **12F 以内** |
| `46` `64` `43` 等の2方向コマンド | 最初の方向から最後の方向まで **10F 以内**、ボタンは最後の方向から **6F 以内** |
| `236` `214` `41236` 等 | 全体 **16F 以内**（斜めの省略は不可、ただし `2→3→6` の `3` は 1F でも可） |
| 溜め `(X)` | 技データの `charge_frames` で定義 |

### 2.3.4 遡及的な同時押し判定（遅延ゼロの同時押し）

1ボタン技は押下フレームで **即座に** 発生させる。その後 2F 以内に2つ目のボタンが押され、同時押し技が成立した場合は、**1つ目の技をキャンセルし、同時押し技を「1つ目の押下フレームから経過済み」として開始する**（技の内部フレームカウンタ = 経過フレーム数）。

- 条件: 1つ目の技がまだ攻撃判定を出していない（発生前）こと。全ての通常技は発生 ≥ 10F のため常に成立する。
- これにより、同時押しを待つための入力遅延を一切入れない。

### 2.3.5 しゃがみと手前回避の曖昧さ解決

`2` は「しゃがみ（押しっぱなし）」と「手前への回避（タップ）」を兼ねる。

1. `2` を押した瞬間に **しゃがみ移行** を開始する（即座に姿勢が下がり始める）。
2. `2` を **5F 以内** に離し、その間に P/K/G の押下がなければ、押下フレームに遡って **手前回避** に変換する（回避の経過フレーム = 押下からの経過フレーム）。
3. 5F を超えて押し続けた場合、または5F以内にボタンが押された場合はしゃがみ（またはしゃがみ技）として確定する。
4. `8` は単独で意味を持たないため、`8` を押した瞬間に即座に **奥回避** を開始する。
5. タップによる回避の対象は **純粋な `8` / `2` のみ**。`7` `9` `1` `3` は回避にならない（コマンド技の入力途中と衝突させないため）。
6. ジャンプは独立した状態としては存在しない（`9K` 等の跳躍技は「技」として個別に定義する）。

### 2.3.6 先行入力（バッファ）

- 技・ガード・被弾などで行動不能な間に入力された技コマンドは、行動可能になる **8F 前から** 受け付け、行動可能になった最初のフレームで発動する（最後に入力された有効コマンドを採用）。
- 連携の次段は、技ごとの `chain_window`（例: 前段ヒット/ガード/空振りの発生フレームから硬直終了 4F 前まで）内の入力で成立する。
- 投げ抜けは先行入力の対象外（§2.8 の専用受付時間で判定）。

### 2.3.7 コマンドの優先順位

同一フレームで複数のコマンドが成立した場合、次の順で **最初に該当したもの** を採用する。

1. 投げ抜け（被投げ中のみ）
2. 受け身・起き上がり動作（ダウン/着地時のみ）
3. 技データの `priority` 値が大きいもの（既定: 同時押しの数 ×100 ＋ コマンド方向の数 ×10）
4. 同値の場合は、より長いコマンド（入力イベント数が多い）
5. それでも同値なら技リスト上で先に定義されたもの

例: `46P+K` (優先 2×100+2×10=220) ＞ `6P+K` (210) ＞ `P+K` (200) ＞ `46P` (120) ＞ `6P` (110) ＞ `P` (100)

### 2.4.2 状態遷移の原則

- 状態遷移は **1フレームにつき1回**、シミュレーションの「状態更新フェーズ」でのみ行う（[11 §11.7](11_technical_architecture.md) のフェーズ順）。
- 各状態は `enter()` / `tick()` / `exit()` を持つ。状態内経過フレーム `state_frame` は enter 時に 0、毎 tick で +1。
- 全ての「行動可能になった」判定は `actionable` フラグで一元管理し、先行入力はこのフラグが立つ 8F 前から評価する。

## 2.5 移動

### 2.5.1 歩き

- `6` 押しっぱなし = 前歩き、`4` = 後歩き。`9` は前歩き、`7` は後歩きとして扱う。`3` / `1` は歩かず **しゃがみ**（§2.5.4）。
- 速度はキャラ別（[04](04_characters.md) の基礎性能表）。歩き始めは 4F かけて最高速度へ線形加速、離すと 3F で停止。
- 後歩きはガードではない（ガードは G ボタン）。

### 2.5.2 ダッシュ・バックダッシュ

| 項目 | 前ダッシュ `66` | バックダッシュ `44` |
|---|---|---|
| 全体 | キャラ別 17〜20F | キャラ別 19〜22F |
| 移動距離 | キャラ別 1.20〜1.60m | キャラ別 0.90〜1.35m |
| 移動カーブ | 立ち上がり 3F で最高速、終盤 6F で減速 | 同左 |
| 行動可能 | 6F目からダッシュ技（`66P` 等）、12F目から全行動 | 12F目からガード・全行動 |
| キャンセル | 10F目から G でガード | 12F目から G でガード |
| カウンター | 全区間でカウンター成立 | 全区間でカウンター成立 |

### 2.5.3 走り

- 前ダッシュの 14F目以降も `6` を押し続け、かつ相手との距離が **2.50m 以上** のとき走りに移行する。
- 加速 0.10 m/s/F で最大 4.50 m/s（キャラ別係数あり）。
- 走り中: `P` 走りパンチ、`K` 走りキック（スライディング等）、`P+G` 走り投げ（タックル系）、`6` を離す / `G` で停止（停止 10F・カウンター成立）。
- 相手との距離が 0.80m 未満になると自動的に「走り停止」に移行する（技入力があれば走り技が優先）。

### 2.5.4 しゃがみ・立ち上がり

- `2`（`1`/`3` を含む）押しっぱなしでしゃがみ。しゃがみ移行 3F（2F目から「しゃがみ」姿勢扱い = 上段がスカる）。
- `2` を離すと立ち上がり 4F。立ち上がり 1〜8F の間に `P`/`K` で「立ち技」（`立ちP` 等、キャラ固有）が出る。
- しゃがみダッシュ（`33`）は一部キャラのみ（技データで定義）。

### 2.5.5 横移動（回避）

| 項目 | 値（全キャラ共通の既定。キャラ別上書き可） |
|---|---|
| 入力 | `8` タップ = 奥へ、`2` タップ = 手前へ（§2.3.5） |
| 全体 | **22F**（キャラ別 20〜24F） |
| 移動 | 対戦軸に垂直に **0.70m**（1〜12F で移動、13F以降は停止） |
| 開始区間 | 1〜3F |
| **回避成立区間** | **4〜14F** |
| 終了区間 | 15〜22F（無防備・カウンター成立） |
| 回避ガード | 8F目以降に `G` を押すと、残りを省略して立ちガードへ移行（8F目に押せば合計 10F） |
| 回避攻撃 | 8〜14F に `P` または `K` で回避攻撃（キャラ固有。最低1種は全キャラ持つ） |
| 投げ | **回避中は全区間で投げられる**（回避は投げに負ける） |

**回避判定ルール（最優先で幾何判定より先に適用）**:

攻撃の **最初の持続フレーム** において、防御側が回避成立区間（4〜14F）にあり、かつその攻撃が回避方向をカバーしていない場合、その攻撃は **防御側に対して空振りが確定** する（以後その技の残り持続フレームで当たることはない）。

| 攻撃の追尾性 `tracking` | 奥回避に対して | 手前回避に対して |
|---|---|---|
| `linear`（直線） | スカる | スカる |
| `half_left`（攻撃者から見て左側をカバー） | 防御側の回避方向が攻撃者の左なら命中、右ならスカる | 同左 |
| `half_right` | 右なら命中、左ならスカる | 同左 |
| `full`（全回転） | 命中 | 命中 |

- 「奥/手前」は画面基準、「攻撃者から見て左/右」はシミュレーション内で攻撃者の向き基準に変換して判定する。
- 回避中の相手に命中した攻撃は **必ずカウンターヒット** になる（「回避狩り」）。
- 回避が成立した（攻撃をスカした）場合、回避した側は終了区間を **6F 短縮** できる（回避成功ボーナス）。これにより直線技の空振り硬直に反撃しやすくなる。
- 演出: 回避成功時に回避した側へ淡い残像エフェクト＋専用SE（ガード音とは明確に異なる「風切り音」）。

## 2.6 ガード

### 2.6.1 ガード操作

- `G` 押しっぱなし = 立ちガード。`G` ＋ `2`（`1`/`3`）= しゃがみガード。
- 待機・歩き・しゃがみ状態からのガード移行は **0F**（押したフレームから有効）。
- ガード中もキャラの向きは自動補正される。背面からの攻撃はガードできない。
- **削りダメージはない**。

### 2.6.2 段と姿勢の関係（全ルールの基礎）

| 攻撃の段 \ 防御側 | 立ちガード | しゃがみガード | 立ち（無防備） | しゃがみ（無防備） |
|---|---|---|---|---|
| **上段** `high` | ガード | **スカり** | ヒット | **スカり** |
| **中段** `mid` | ガード | **ヒット** | ヒット | ヒット |
| **下段** `low` | **ヒット** | ガード | ヒット | ヒット |
| **特殊中段** `smid`（主に肘・低い拳） | ガード | ガード | ヒット | ヒット |
| **投げ** `throw` | 成立 | スカり | 成立 | スカり |
| **下段投げ** `lthrow` | スカり | 成立 | スカり | 成立 |
| **ダウン攻撃** `down` | ダウン中の相手にのみ当たる | — | — | — |

- 「スカり」は **幾何判定に関わらず必ず空振り** とする（ルールが優先）。
- 技の姿勢フラグ: 技データの `posture` で、特定フレームに「しゃがみ扱い（上段をスカす）」「空中扱い（下段をスカす）」を付与できる（例: 低姿勢の突進技、跳び膝）。

### 2.6.3 ガード硬直とノックバック

- ガード硬直は技データの `on_block`（ガード時有利フレーム）から自動算出する（§2.12）。
- ガード時の押し戻し距離は技データ `block_push`（既定: 弱 0.15m / 中 0.25m / 強 0.40m）。防御側が壁/柵/縁に接している場合、押し戻しは攻撃側に反映される。
- **ガードによる押し戻しではリングアウトしない**（縁で停止する）。
- `guard_crush` フラグを持つ技（溜め最大など、ごく一部）はガードさせると「ガード崩れ」（ノーダメージだが大きく不利）を起こす。

## 2.7 ヒット・カウンター・被弾リアクション

### 2.7.1 通常ヒット

- ヒット硬直は技データ `on_hit` から自動算出する（§2.12）。
- 被弾リアクションは技データ `hit_reaction`（§2.7.4）で指定する。

### 2.7.2 カウンターヒット（CH）

- **成立条件**: 防御側が以下のいずれかの状態のときにヒットした場合。
  - `ATTACK` 状態の全区間（発生前・持続・硬直）
  - `THROW_TRY` の空振り硬直
  - `DASH_F` / `DASH_B` / `RUN` / 走り停止
  - `EVADE` の終了区間（15F以降）、および回避中の相手に回転技が命中した場合
  - `WAKEUP` 中の起き上がり攻撃
- **効果**:
  - ダメージ ×**1.25**（端数切り捨て）
  - 有利フレームは技データ `on_ch`（未指定時は `on_hit + 3`）
  - リアクションは `ch_reaction`（未指定時は `hit_reaction`）。CH 時のみよろけ・浮き・吹き飛びになる技を多数用意し、CHの価値を高める
  - 演出: 「COUNTER」表示、専用ヒットスパーク（朱色）、重めのSE、ヒットストップ +3F

### 2.7.3 ヒットストップ

被弾・ガードの瞬間、**両者のシミュレーションを一時停止** して打撃の重さを伝える。ヒットストップ中も入力履歴は記録し、先行入力に使える。有利フレームの計算にはヒットストップを含めない。

| 強さ `weight` | ヒット | ガード | CH 追加 |
|---|---|---|---|
| `light` | 6F | 5F | +3F |
| `medium` | 8F | 6F | +3F |
| `heavy` | 11F | 8F | +3F |
| `launch` | 10F | 7F | +3F |
| `finisher`（ラウンド決着打） | 20F | — | — |

- コンボ中（空中ヒット）は各ヒットストップを 2/3（切り捨て）にしてテンポを保つ。

### 2.7.4 被弾リアクション一覧

| リアクションID | 内容 | 主な用途 |
|---|---|---|
| `high_light` / `high_heavy` | 上半身のけぞり（左右・強弱） | 上段打撃 |
| `mid_light` / `mid_heavy` | 腹部のけぞり | 中段打撃 |
| `low_light` | 足元のけぞり | 下段打撃 |
| `gut_crumple` | 崩れ落ち（`CRUMPLE`、60Fで前のめりダウン） | 中段CH大技 |
| `stagger_gut` / `stagger_leg` | よろけ（§2.7.5） | 中段/下段の重い技 |
| `knockback` | 後方へ吹き飛び → ダウン | 上中段の重い技 |
| `spin` | 回転しながら吹き飛び → うつ伏せダウン | 回転系の重い技 |
| `trip` | 足払い転倒（その場ダウン） | 下段の払い技 |
| `launch` | 浮き（`AIRBORNE`、技データの打ち上げ速度に従う） | 浮かせ技 |
| `launch_spin` | きりもみ浮き | 一部の浮かせ技 |
| `wall_splat` | 壁張り付き（壁到達時のみ） | 壁際での重い技 |
| `turn_around` | 背向けにさせる（相手が背向けのけぞり） | 一部の技 |
| `guard_crush` | ガード崩れ | `guard_crush` 技のガード時 |

### 2.7.5 よろけ（STAGGER）

- 基本持続は技データ `stagger_frames`（例: 腹よろけ 36F、足よろけ 30F）。
- 防御側は **レバガチャ（方向の変化・ボタン押下の各新規入力ごとに 1F 短縮）** で回復を早められる。最大短縮 = 持続の 50%。
- 攻撃側は固定の有利（技データ `on_hit` はよろけ最短時に対して定義）を得る。防御側が回復した瞬間に行動可能（ガード可）。
- UI: よろけ中の防御側の頭上に回復ゲージ（ガチャ量に応じて縮む）を表示（トレーニングでは常時、対戦では設定で表示/非表示）。

### 2.7.6 相打ち

両者の攻撃が同じフレームにヒットした場合、両者とも通常ヒット（カウンターにはしない）。各自のダメージ・リアクションを適用する。片方が浮かせ技の場合は浮いた側のみ空中状態になる。

## 2.8 投げ

### 2.8.1 基本

| 項目 | 値 |
|---|---|
| 入力 | `P+G`（方向付き `6P+G` `4P+G` `46P+G` `41236P+G` 等、キャラ別に 4〜8種） |
| 発生 | **10F**（コマンド投げは 10〜14F） |
| 成立判定 | 発生フレームの1フレームのみ。中心間距離 ≤ キャラ別の **投げ間合い**（0.85〜1.05m）、かつ相手が投げられ可能状態であること |
| 方向 | 正面（±60°）で通常投げ、側面（60〜120°）で側面投げ、背面で背後投げに **自動変化** |
| 空振り | 空振り硬直 **20F**（全体 30F）、カウンター成立 |
| 投げられ不可 | 相手が `ATTACK` の発生前・持続中、しゃがみ（通常投げ）、空中、ダウン、ヒット/ガード硬直中とその解除後 2F |
| 打撃との競合 | 同一フレームで打撃が持続に入る場合は **打撃が勝つ** |
| 投げ同士 | 同一フレームで両者の投げが成立 → **投げ合い**（双方弾かれて 0F 五分で離れる） |
| ダメージ | 通常投げ 220〜320、大技・コマンド投げ 300〜380、下段投げ 200〜280 |

### 2.8.2 投げ抜け

- 各投げには **抜け方向** `escape`（`N` / `4` / `6` / `2` のいずれか、コマンド投げは技データで指定）がある。
  - 標準: `P+G` → `N`、`6P+G` → `6`、`4P+G` → `4`、`46P+G` → `6`、`2P+G`（下段投げ）→ `2`
- **受付**: 投げの発生フレームの **8F 前から 発生後 7F まで（計 15F）** に、防御側が `抜け方向 + P+G` を入力すると投げ抜けが成立する。
- 防御側の入力は、受付期間中の **直近 2種類の方向** まで有効（例: `N P+G` と `6P+G` を両方入れておけば、どちらの投げも抜けられる）。3種類目を入れると最も古いものが無効になる。
- 抜け成功: 双方離れて **防御側 +2F** 有利。専用SE・「投げ抜け」表示（トレーニング時）。
- 注意: 防御側が受付期間中にガードを解いて `P+G` を入力すると、それは自分の投げの試み（`THROW_TRY`）にもなりうる。**被投げ判定が先**（§2.3.7 の優先順位1）。
- 投げコンボ（多段投げ）の各段は、それぞれ独立した抜け方向・受付（各段の入力から 15F）を持つ。
- アシスト設定（オフライン限定・任意）: 「投げ抜け簡易化」ON で、方向に関わらず `P+G` で全ての通常投げを抜けられる（コマンド投げは不可）。

### 2.8.3 投げの演出データ

投げはペアアニメーション（攻撃側と防御側が同期する）で再生する。防御側のルート位置は攻撃側ルートからの相対変換として毎フレームデータで持ち、シミュレーション上の位置もデータに従う（[12 §12.4](12_data_formats.md)）。投げ後の位置関係（入れ替え・背向け・ダウン向き）とリングアウト可否（`can_ringout`）はデータで定義する。

## 2.9 浮き・空中コンボ

### 2.9.1 物理

- 浮き状態のファイターは放物運動する: `vy -= gravity` を毎フレーム。
- 重力（Q16.16 で表現、ここでは m/F² で記載）: 基準 **0.0065 m/F²** × キャラの `float_factor`（軽量級 0.92〜重量級 1.10）。
- 浮かせ技は `launch: {vy, vx}` を持つ（例: 中浮かせ `vy = 0.110 m/F` → 頂点約 0.93m、滞空約 34F）。
- 空中で追撃を受けるたびに:
  - 新たな上向き速度 = 技データ `air_launch_vy` × 減衰 `0.86^(空中被弾数)`
  - 重力 += 基準の 5%（空中被弾数ごとに累積）
  - 空中被弾数が **8** に達すると強制落下（以後は空中ヒットしない「落下」状態）
- 着地: `y ≤ 0` で `KNOCKDOWN` へ。着地の瞬間に受け身判定（§2.10.2）。

### 2.9.2 コンボ補正

| ヒット | 補正率 |
|---|---|
| 浮かせ技（始動） | 100% |
| 空中2ヒット目 | 85% |
| 3ヒット目 | 70% |
| 4ヒット目 | 60% |
| 5ヒット目以降 | 50% |
| 壁ヒット後の追撃 | 上記にさらに ×0.80 |
| よろけ/崩れ中への追撃 | 1ヒット目 90%、以降は上記テーブル |
| ダウン追い打ち | 固定ダメージ（技データ。補正なし、ただしコンボ後は ×0.5） |

- 補正後ダメージは端数切り捨て、最低 1。
- **コンボダメージの目安**: 中浮かせからの基本コンボ 300〜380、壁コンボ込みの最大 420〜480（体力の約45%）。これを超えるコンボが見つかった場合はバランス調整の対象とする。

## 2.10 ダウン攻防

### 2.10.1 ダウンの向き

着地時の姿勢により4種類: `FACE_UP_HEAD_NEAR`（仰向け・頭が相手側）、`FACE_UP_FEET_NEAR`、`FACE_DOWN_HEAD_NEAR`、`FACE_DOWN_FEET_NEAR`。向きごとに起き上がり動作とアニメーションが異なる。

### 2.10.2 受け身

- 着地フレームの **前 4F 〜 後 5F**（計 10F）に `G` を押すと受け身が成立。
  - `G` のみ: その場受け身（全体 22F、11F目からガード可）
  - `8G` / `2G`: 横受け身（奥/手前へ転がる、全体 26F）
  - `4G`: 後ろ受け身（後方へ 1.0m、全体 26F）
- 受け身中は 1〜10F が打撃無敵（投げも不可）、11F 以降は通常。
- `no_tech`（受け身不可）フラグの技・投げの後は受け身できない（ダウン攻撃が確定しうる）。

### 2.10.3 ダウン中の行動（受け身を取らなかった場合）

ダウンしてから **20F 経過後** に入力を受け付ける。最大 **120F** で自動的にその場起き。

| 入力 | 行動 | 全体 | 性質 |
|---|---|---|---|
| `G` | その場起き | 26F | 1〜12F ダウン攻撃以外の打撃に無敵ではない（ダウン扱い）、19F〜 ガード可 |
| `8` / `2` | 横転起き（奥/手前へ 0.8m） | 30F | 1〜14F ダウン攻撃無敵 |
| `4` | 後転起き（後方 1.2m） | 30F | 1〜14F ダウン攻撃無敵。リング縁では不可（その場起きに変化） |
| `K` | 起き上がり中段蹴り | 発生 20F | 中段、ダメージ 60、ガード -14F、ヒットでダウン |
| `2K` | 起き上がり下段蹴り | 発生 22F | 下段、ダメージ 50、ガード -17F、ヒット +2F |
| 無入力 | 寝っぱなし | — | 最大120F |

- 起き上がり攻撃のフレーム・ダメージは全キャラ共通値を既定とし、モーションのみキャラ固有。
- ダウン中のファイターは「ダウン姿勢」の喰らい判定を持ち、`down` 段の攻撃と `hits_down: true` の技（一部の下段）のみが当たる。

### 2.10.4 ダウン攻撃

| コマンド | 種類 | 発生 | ダメージ | 空振り/ガード時 | 備考 |
|---|---|---|---|---|---|
| `8P` | 飛びかかり（大ダウン攻撃） | 24〜28F | 100〜130 | 着地硬直大（-30F相当） | 横転で避けられる |
| `2P` | 小ダウン攻撃 | 14〜16F | 30〜45 | -12F | 確定状況が多い |

## 2.11 リング・壁・リングアウト

### 2.11.1 境界の種類

ステージの境界は多角形の各辺に種類を持つ（[05](05_stages.md)、[12 §12.6](12_data_formats.md)）。

| 種類 | 地上で押される | 浮き・投げ・吹き飛び | 備考 |
|---|---|---|---|
| `open`（縁） | 縁で停止（自発移動・ガード押し戻しでは出ない） | **リングアウト** | 被弾硬直・浮き・被投げ・吹き飛び中に中心が縁を越えたらリングアウト |
| `fence`（低い柵、高さ 0.6〜0.9m） | 壁として機能 | 浮きの高さが柵高を超えていればリングアウト、超えなければ壁ヒット | `can_ringout` 投げは柵越えでリングアウト |
| `wall`（壁） | 壁 | 壁ヒット | リングアウトなし |
| `breakable`（破壊壁） | 壁 | 壁ヒットで耐久値を減らし、0 で破壊 → 以後 `open` または拡張床 | 耐久 2（既定）。重い技の壁ヒットで -1、`wall_break` 技で即破壊 |

### 2.11.2 リングアウト

- 判定: 該当状態のファイターの中心（押し合い円の中心）が `open` 辺を越えたフレームで成立。
- 効果: **体力に関係なく、そのラウンドは落ちた側の負け**。
- 両者が同一フレームでリングアウトした場合は引き分け（§2.14）。
- 演出: カメラが落下を追う専用ショット、「RING OUT」表示、ステージ別の落下演出（水しぶき、砂煙など）。

### 2.11.3 壁ヒット

- 被弾硬直・吹き飛び・浮き中のファイターが、水平速度 ≥ 0.02 m/F で壁/柵に接触すると壁ヒット。
  - 地上: `wall_stagger`（壁よろけ 30F、攻撃側は追撃可能）
  - 空中、または技が `wall_splat` を持つ場合: 壁張り付き（40F、空中コンボ扱いで追撃可能）
- **1コンボにつき壁ヒットは1回まで**（2回目以降は通常のダウンになる）。
- 壁際でのガード: 押し戻しは攻撃側にかかる。

### 2.11.4 縁際の挙動

- 自発移動（歩き・ダッシュ・回避・バックダッシュ・後転起き）では縁を越えない。縁の手前 0.05m で停止する。
- 縁に背を向けた状態でガードしている相手には、リングアウトさせられる技（吹き飛び・投げ）が最大の脅威となる。これが本作の「縁の読み合い」の核である。

## 2.12 フレームデータの定義と自動算出

### 2.12.1 用語

| 用語 | 定義 |
|---|---|
| 発生 `startup` | 攻撃判定が初めて出るフレーム番号（1始まり）。例: 発生10F = 10F目に判定が出る |
| 持続 `active` | 攻撃判定が出ているフレーム数 |
| 硬直 `recovery` | 最後の持続フレームの翌フレームから、行動可能になるまでのフレーム数 |
| 全体 `total` | `startup + active - 1 + recovery`（自動算出、データには書かない） |
| ガード時 `on_block` | 持続1F目にガードされた場合の、攻撃側から見た有利フレーム（+は攻撃側有利） |
| ヒット時 `on_hit` | 持続1F目にヒットした場合の有利フレーム。ダウン/浮きを伴う場合は `"KD"` / `"LAUNCH"` と表記 |
| CH時 `on_ch` | カウンターヒット時の有利フレーム |

### 2.12.2 硬直の自動算出（本作の重要な設計判断）

データには **有利フレーム** を書き、防御側の硬直は **エンジンが算出する**。これにより「表示値と実挙動の一致」を構造的に保証する。

```
接触フレーム c（持続の何F目で当たったか、1始まり）
攻撃側の残り行動不能フレーム R = (active - c) + recovery
防御側の硬直 S = R + adv（adv = on_block / on_hit / on_ch）
```

- 持続の後半で当たった場合（c > 1）、攻撃側の残りが減るため、自然に有利が増える（現実の格闘ゲームと同じ挙動）。
- `S < 1` になる場合は 1 とする（ありえない設定はデータ検証で弾く）。
- ヒットストップは両者に同量入るため有利計算に影響しない。

### 2.12.3 設計ガイドライン（全キャラ共通の基準値）

| カテゴリ | 発生 | ガード時 | ヒット時 | ダメージ | 例 |
|---|---|---|---|---|---|
| 最速上段（ジャブ） | 10F | +1 | +4 | 45〜55 | `P` |
| 最速しゃがみパンチ | 11F | -4 | +3 | 35〜45 | `2P`（下段） |
| 速い中段（肘・中段突き） | 12〜14F | -3〜+1 | +3〜+6 | 70〜100 | `6P` 系 |
| 中段蹴り | 15〜18F | -6〜-2 | +3〜+7 / CH でよろけ等 | 100〜140 | `3K` 系 |
| 浮かせ技（速い） | 14〜16F | -14〜-11 | LAUNCH | 90〜130 | `立ちP` 等 |
| 浮かせ技（遅い・リーチ長） | 18〜22F | -9〜-5 | LAUNCH | 120〜160 | 跳び膝等 |
| 下段（速い） | 13〜15F | -8〜-5 | +1〜+4 | 40〜60 | `2K` |
| 下段（ダウン） | 18〜24F | -16〜-12 | KD | 70〜110 | 足払い |
| 回転技（半回転） | 16〜22F | -8〜-4 | KD / +3〜 | 90〜130 | |
| 全回転技 | 20〜26F | -12〜-8 | KD | 100〜140 | 後ろ回し蹴り等 |
| 投げ | 10F | — | — | 220〜320 | `P+G` |

**確定反撃の原則**:
- ガード時 **-10F 以下** は最速技（10F）で確定反撃を受ける。
- 浮かせ技は全てガード時 **-11F 以下**（＝必ず何らかの反撃が確定）。-14F 以下の浮かせ技は、相手の最速浮かせ（14〜15F）で浮かされうる。
- 全キャラが **10F の上段**、**12〜14F の中段**、**14〜16F の浮かせ技（いずれかの姿勢から）** を必ず持つ（反撃手段の公平性）。

## 2.13 判定（当たり判定）

### 2.13.1 判定ボリュームの種類

| 種類 | 形状 | 用途 |
|---|---|---|
| 押し合い | 鉛直円柱（半径 0.26〜0.34m、キャラ別） | キャラ同士の重なり防止・壁/縁との衝突 |
| 喰らい判定 | カプセル 11本（頭、胸、腹、左右上腕、左右前腕、左右大腿、左右下腿） | 攻撃を受ける部位 |
| 攻撃判定 | 球またはカプセル（技ごと 1〜3個、ボーン追従） | 攻撃の当たる部位 |
| 投げ判定 | 距離＋角度判定（形状なし） | §2.8 |

- 喰らい判定と攻撃判定は、アニメーションから **ビルド時に固定小数点でベイク** した値を使う（[09 §9.6](09_art_animation_camera_vfx.md)）。実行時にスケルトンを参照しない。

### 2.13.2 判定処理の順序（1フレーム内）

1. 押し合い解決（両者の円柱が重ならないよう、重なり量の半分ずつ押し戻す。壁/縁側は動かさない）
2. 投げ判定（発生フレームの投げのみ）
3. 打撃判定: 各攻撃判定 × 相手の喰らい判定のカプセル間最短距離 ≤ 半径和
4. ルールによる上書き（優先順）:
   1. 無敵フラグ（受け身・起き上がり等）
   2. 回避判定ルール（§2.5.5）
   3. 段と姿勢のルール（§2.6.2、技の `posture` フラグ）
   4. 1技につき同一相手へのヒットは1回（多段技は `hit_group` ごとに1回）
5. ヒット/ガード/カウンター/相打ちの確定とイベント発行

### 2.13.3 リーチの目安

技データには参考値として `reach`（攻撃判定の最大到達距離、中心間距離 m）を自動算出して記録する（トレーニングモードの表示と AI の間合い判断に使う）。

## 2.14 ラウンドの流れ

| フェーズ | 内容 | 時間 |
|---|---|---|
| 登場 | 1ラウンド目のみ、両キャラの登場演出（スキップ可） | 各 2.5秒 |
| ROUND コール | 「ROUND 1」等の表示＋アナウンス | 1.5秒 |
| FIGHT | 「FIGHT」表示の瞬間から入力受付・タイマー開始 | — |
| 対戦 | — | 最大45秒 |
| 決着 | KO / RING OUT / TIME UP の表示。KO 時はスローモーション（演出のみ、0.35倍速で 45F） | 2〜3秒 |
| KOリプレイ | 最後の 4秒をカメラ演出付きで再生（設定で ON/OFF、タップでスキップ） | 4秒 |
| 勝利ポーズ | 勝者のポーズ＋セリフ | 2.5秒（スキップ可） |

- **タイムアップ**: 残り体力の **割合** が高い方の勝ち。同値なら引き分け。
- **引き分け**: 両者にラウンドポイント。両者が同時に勝利条件を満たした場合は **延長ラウンド**（体力満タン、30秒）を1回行う。延長も引き分けなら試合引き分け（アーケードでは敗北扱い）。
- **ダブルKO**: 引き分けとして扱う。
- **PERFECT**: 無傷でラウンドを取った場合、「PERFECT」表示（スコアボーナスのみ、勝敗への影響なし）。
- ラウンド間で体力は全快。位置は初期配置に戻る。

## 2.15 全キャラ共通動作（技表に載せない共通部分）

- 歩き・ダッシュ・走り・横移動・しゃがみ・ガード・振り向き
- 受け身・起き上がり各種（§2.10）
- 投げ抜け（§2.8.2）
- 被弾リアクション全種（§2.7.4）
- KO・リングアウト落下・勝利/敗北モーション

これらはキャラごとにアニメーションを持つが、フレームデータは共通値を既定とし、キャラ別の上書きはデータの `overrides` に明示する。

## 2.16 シミュレーションから発行されるイベント（演出・AI・ログ用）

シミュレーションは状態を変化させるだけでなく、以下のイベントをフレームごとのキューに積む。演出層（グラフィック・サウンド・UI）は **イベントと状態だけを読み**、シミュレーションへ書き込まない。

| イベント | 主なペイロード |
|---|---|
| `MoveStarted` | player, move_id |
| `HitConfirmed` | attacker, defender, move_id, damage, hit_type（normal/ch/side/back）, hit_level, contact_point, reaction, combo_count |
| `Blocked` | attacker, defender, move_id, contact_point, guard_type |
| `Whiffed` | attacker, move_id, reason（range/evade/high_vs_crouch/...） |
| `EvadeSucceeded` | evader, move_id |
| `ThrowStarted` / `ThrowEscaped` / `ThrowClash` | player, throw_id |
| `Launched` / `Landed` / `Teched` | player, tech_type |
| `WallHit` / `WallBroken` | player, wall_id |
| `RingOut` | player, edge_id |
| `Staggered` / `StaggerRecovered` | player, frames |
| `RoundEnded` | winner, reason（KO/RINGOUT/TIMEUP/DRAW）, perfect |
