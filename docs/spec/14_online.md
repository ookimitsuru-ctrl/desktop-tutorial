# 14 オンライン対戦（v1.x・後期フェーズ）

> v1.0 ではオンライン対戦を実装しない。ただし **v1.0 の設計はオンライン化を妨げてはならない**（決定論・状態スナップショット・入力の抽象化・イベント重複排除を v1.0 で実装済みにする）。本章はその前提と、v1.x での実装方針を定める。

## 14.1 方式

| 項目 | 決定 |
|---|---|
| 同期方式 | **ロールバック方式**（入力遅延＋予測＋巻き戻し再計算） |
| 入力遅延 | 既定 2F（設定で 1〜4F、または回線品質から自動） |
| 最大ロールバック | 7F（これを超える遅延は入力遅延の増加で吸収、さらに超えると一時停止） |
| 対戦形式 | 1対1、P2P（直接通信）、通信不可時はリレーサーバー経由 |
| トランスポート | UDP（Godot の `PacketPeerUDP` または ENet）。NAT 越えが必要な場合は WebRTC データチャネル（`webrtc-native` 拡張、Android 対応版） |
| サーバー | マッチング・シグナリング用の小規模サーバー（任意のクラウド。WebSocket）、STUN/TURN |
| 互換性 | ゲームバージョンとデータハッシュが一致する相手とのみ対戦 |

## 14.2 ロールバックの流れ

```
毎 Tick:
  1. ローカル入力を取得し、(現在フレーム + 入力遅延) のフレームの入力として記録・送信
  2. 受信したリモート入力を記録
  3. もし過去フレームのリモート入力が「予測と異なって」届いたら:
       → そのフレームの保存状態へ load_state()
       → 確定入力・予測入力で現在フレームまで step() を再実行（描画・音は行わない）
  4. 現在フレームを step()（リモート入力が未着なら「直前の入力を継続」と予測）
  5. save_state()（リングバッファ、8 フレーム分）
  6. 描画は最新状態から行う。イベントは重複排除して演出に渡す
```

- **予測**: 未着のリモート入力は「最後に受信した入力の held を継続、pressed/released はなし」と予測する。
- **同期確認**: 両者は確定フレームのチェックサムを 30F ごとに交換し、不一致なら「同期エラー」として試合を中断し、両者の入力ログとスナップショットを保存する（バグ報告用）。
- **時間同期**: 両者のフレーム進行差を測り、先行している側が 1 Tick 待つ（最大 1F/秒）ことで、片方だけが常にロールバックする状況を防ぐ。

## 14.3 v1.0 で満たしておく前提（オンライン準備チェックリスト）

- [ ] `SimWorld` は Node 非依存・浮動小数点不使用（[11 §11.4](11_technical_architecture.md)）
- [ ] `save_state()` / `load_state()` が全状態を完全に保存・復元し、1回 0.05ms 以下
- [ ] 1 Tick のシミュレーションが最低ティアで ≤ 1.2ms（7F ロールバック＋通常 1F で 9.6ms 以内）
- [ ] 異なる端末（ARM 実機と x86_64 CI）で同一リプレイのチェックサムが一致
- [ ] 演出層が「状態から見た目を決める」作りで、巻き戻しで破綻しない
- [ ] VFX / SE のイベント重複排除
- [ ] AI・リプレイ・ネットの入力源を `InputFrame` で抽象化

## 14.4 モード

| モード | 内容 |
|---|---|
| ルームマッチ | ルームコード（6桁）を共有して友人と対戦。連戦、キャラ変更 |
| ランクマッチ | 段位ベースのマッチング（レーティング: Glicko-2）。2本先取・45秒固定、アシスト機能無効 |
| 観戦 | （任意）ルーム内の観戦者へ入力ストリームを配信 |

## 14.5 セキュリティとプライバシー

- アカウント登録不要。端末で生成したランダム ID と、任意の表示名（最大 12 文字、NG ワードフィルタ）のみ。
- IP アドレスは P2P のため相手に知られうることを、オンライン初回利用時に明示して同意を得る（リレーのみモードを選択可）。
- 不正対策: 入力のみを送る方式のため状態改ざんは同期エラーで検出される。ランクマッチではデータハッシュの一致を必須とする。
- 通信は全てバージョン付きのバイナリプロトコルで、受信データの長さ・範囲を必ず検証する。

## 14.6 追加の権限・ストア要件

- `INTERNET` 権限の追加。Google Play 公開時はデータセーフティの申告（収集データ: 表示名・ランダム ID・対戦記録）。
- サーバーの運用コストと、停止時の扱い（オフライン機能は全て継続して使える）を明示する。
