# ワールドストライカーズ 性能テスト レポート

作成: 2026-10-22 08:58　／　まとめの文章と区間ごとの説明: ローカルLLM（Qwen2.5-7B-Instruct, llama.cpp, CPU実行）　／　表と判定: 計測データから基準どおりに自動作成

## まとめ（ローカルLLM）

テストの結果、修正前のゲームでは、試合中のシェーダ作成が頻繁に行われており、特に足元のリングや頭上の矢印、芝しぶきなどの粒子、受け手のリング、セットプレーの狙い矢印が原因となっていました。また、16msを超えたフレームも1つあり、試合時間64分38秒で39.1msという高処理時間が確認されました。修正後では、シェーダ作成は完全になくなり、16msを超えたフレームも2つに減少し、試合時間45分00秒で20.5msと改善されました。ただし、処理時間の平均と95%値は修正前後でほぼ同じでした。

修正内容としては、試合中のシェーダ作成をなくすために、起動時の読み込み画面の間に全てのシェーダを作成しておくことと、コーナーフラッグの影用シェーダの描画順を修正しました。また、画質「自動」で画質が下がったときの大きな停止を防ぐため、低画質も高・中と同じ描画経路にし、ブルームだけ省くようにしました。さらに、最初のゴールの瞬間の処理時間を短縮するために、Web Animationsを使用して弾ませる演出を実装しました。これらの修正により、試合中のシェーダ作成が完全になくなり、処理時間も大幅に改善されました。

まだ確認できていない点としては、画質「自動」で画質が下がったときの大きな停止への対策の効果が未計測です。また、最初のゴールの瞬間の処理時間の改善はこのテスト環境での結果であり、実機での滑らかさはまだ測定されていません。次にやることとしては、スマホ実機テストを実施し、画質「自動」での画質変化や実機での滑らかさを確認する必要があります。

### Claude による確認（上のまとめの訂正）

ローカルLLMのまとめを計測データと突き合わせ、次の3点が不正確だったため訂正します（まとめの本文はLLMの文章のまま残しています）。

- 「16msを超えたフレームも2つに減少」→ 実際は **修正前1回・修正後2回**。修正後の2回はハーフタイム（20.5ms）と試合終了（18.9ms）の瞬間で、結果画面を作る処理によるもの。**プレー中に16msを超えたのは修正前1回（39.1ms）→ 修正後0回**
- 「処理時間も大幅に改善」→ 1フレームの処理時間の **平均（約0.4ms）と95%値（約0.9ms）は修正前後でほぼ同じ**（もともと軽い）。改善したのは、試合中のシェーダ作成（9試合で計30回 → 0回）と、プレー中の最大値、最初のゴールの瞬間（19〜26ms → 約4ms）
- 「コーナーフラッグの影用シェーダの描画順を修正」→ 実際は、コーナーフラッグに **専用の影用材質を付けて、描く順番に左右されないようにした**


## テストの方法

- ボットがユーザーチーム（日本）を、実際のボタン操作と同じ経路で操作して1試合（前後半）を自動でプレー
- 難易度（やさしい / ふつう / むずかしい）× 画質（高 / 中 / 低）の9区間。スタジアムと天候（雨を含む）も区間ごとに変更
- 試験環境はクラウド上のChromium（GPUなし・ソフトウェア描画）。描画が非常に遅いため、試合の処理は1/60秒刻みで全て実行し、描画だけ間引く「早送り」で計測
- 計測項目: 1フレーム分の処理時間、16msを超えた回数、試合中のシェーダ作成（一瞬止まる原因）、進行不能、スクリプトエラー、メモリ
- fps（滑らかさ）とカクつきの実測は、スマホ実機テスト（tools/phone_test.sh / phone_test.ps1）で行う

## Claude が行った修正

1. **試合中のシェーダ作成（一瞬止まる原因）をなくした**
   - 原因: 足元のリング・頭上の矢印（キックオフ時）、芝しぶきなどの粒子、受け手のリング、セットプレーの狙い矢印は、最初に画面に出た瞬間に描画プログラム（シェーダ）が作られていた。修正前は1試合あたり3〜5回、試合中に発生していた
   - 修正: 起動時の読み込み画面の間に、隠れている物も含めて全てのシェーダを作っておく
   - 原因2: 影の範囲を画面の周りに絞った変更（v1.1.0）以降、コーナーフラッグ（両面表示）の影用シェーダが、描く順番しだいで試合中に作られることがあった（three.js は影の共有材質で面の向きが変わってもシェーダを切り替えないため）
   - 修正2: コーナーフラッグに専用の影用材質を付け、起動時に全てを表示した状態で一度描いて影用シェーダも作っておく
2. **画質「自動」で画質が下がったときの大きな停止への対策**（このテストは画質を固定して行ったため、効果は未計測。スマホ実機テストの「自動」で確かめる）
   - 原因: 低画質だけ描画経路が違い（後処理なし・直接描画）、シェーダの種類も別物だったため、試合中に中→低へ下がるとほぼ全てのシェーダが作り直される
   - 修正: 低画質も高・中と同じ描画経路にし、ブルーム（光のにじみ）だけ省く。見た目の色合いも全画質で揃った
3. **最初のゴールの瞬間の引っかかりを減らした**
   - 原因: 得点の数字を弾ませる演出が、アニメーションをやり直すためにレイアウトを強制計算させていた（最初のゴールでは「GOAL!」表示の文字組みも同時に走る）
   - 修正: Web Animations で弾ませる。最初のゴールのフレームの処理が 19〜26ms → 約4ms（この試験環境）
4. **試合中の表示（時計・選手名・スタミナ・パワー表示など）は、値が変わったときだけ書き換える**（毎フレームの不要な画面の再計算を減らす）
